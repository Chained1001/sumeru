# sumeru

人类作家的灵感素材库：素材分十一个类型族收进结构化库（故事零件、写作方法、作品案例、现实避坑四大桶），可派子代理联网调研时事、热梗、历史等主题素材，写作前按类型检索取用。给网文作者自己用。

状态：实验

## 安装

```bash
npx skills add Chained1001/sumeru
```

前置条件：Node.js 24 及以上、git（提交前校验钩子需要）。版本不足时 `npm test` 第一步会给中文提示。

安装后确认：触发 material-vault，按第一问选「故事零件」、第二问选「人物设定」，给一段路飞式角色描述，应先见两问、后产出落对目录的人设卡与 INDEX.md。

## 五分钟上手

装上之后，你对自己的 AI 助手说话就行，不用敲命令。入口只有两问：这算四个桶里的哪一桶（故事零件、写作方法、作品案例、现实避坑），再挑该桶下的类型族（共十一个）。下面五句话各试一遍，每句后面是试对了该看到的东西。

1. 收一条素材：「这个开局点子你帮我收一下：主角重生回高考前三天，发现全班同学都记得上一次的人生。」
   你该看到什么：先问你收进哪个桶，再给该桶的类型族菜单让你挑；然后产出一张卡落到 `素材库/故事零件/开书点子/`，并更新 `素材库/INDEX.md`。**这一族的卡默认标「私有：是」**，任何导出（打包给写作助手那种）都不会带上它——这是有意的：点子最容易被人抄走，不外流。

2. 只有主题、没有素材：「帮我调研一下明末党争，我想写个穿到东林党身上的。」
   你该看到什么：先问清收进哪一族，再联网取材；回来的卡上带来源与日期，调研过程记录写在 `辅助内容/临时文件/` 下，整篇长文不进库。

3. 要写东西、先找参考：「我要写个疯批反派，库里有能用的吗？」
   你该看到什么：按类型去库里检索，每条给要点、摘录或事实要点、卡路径，只在对话里给，不往库里写新卡。

4. 改一张已有的卡：「第 1 句收的那张点子卡，要点写歪了，帮我改一下。」
   你该看到什么：先在 `素材库/INDEX.md` 里按卡名或要点找到那张卡，改的是那张卡本身；找不到会停下来问你要路径，不猜也不覆盖。

5. 看看库况：「库里现在有多少卡？哪一类太薄？」
   你该看到什么：总卡数、四个桶各多少、各族多少、最近收的卡、待补处数、待复审张数，以及偏薄的族。

如果它没按预期走——比如不问类型就直接建卡——直接说「按 SKILL.md 的两问来」，它会回到入口重问。

两个最容易误会的点：

- **`demo-vault/` 是别人的库**，随技能分发，只作学习用。不要往里加东西：它是分发内容，下次更新会被覆盖。你说「就存这儿」时，它也会另建一个真库，不往示范库里写。
- **素材库默认建在当前目录的 `素材库/`**。找不到库时它会先问你是新建还是指向已有的，不会自动建；想放别处，直接告诉它路径。

## 技能列表

| 技能 | 用途 | 扩展键 |
|---|---|---|
| material-vault | 灵感素材库：入口两问定类型（四大桶、十一个类型族、子类开放），素材在手走采集，只有主题派调研员联网取材（权威源分级取信、大陆源默认政策、来源等级四档含存疑），写作前按类型路由检索；原型基底、节奏样例、伏笔清单整存，组件卡可拆并联；事实与推断分层标注 | 无 |

扩展键只填实际用到的，没有就写「无」，多个用逗号分隔。可填哪些键见 `docs/规范/01-技能写法.md` 的 frontmatter 表。表与 `skills/` 目录的一致性由 `npm run validate` 检查。

## 目录

| 路径 | 说明 |
|---|---|
| `skills/` | 技能源码，唯一发布内容 |
| `templates/` | 新建技能用的模板，不要删 |
| `docs/规范/` | 开发标准 |
| `scripts/`、`test/`、`evals/` | 校验、测试、评测 |

## 开发

| 命令 | 作用 |
|---|---|
| `npm run validate` | 静态校验 `skills/` 与 README 技能表 |
| `npm test` | 运行全部测试 |
