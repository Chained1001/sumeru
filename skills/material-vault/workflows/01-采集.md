# 01 采集

所属技能：material-vault。入口见 `../SKILL.md`。

## 目的

把用户带上门的素材，经对应大类的采集员抽成组件卡，按注册表归档并更新索引。

## 输入

| 字段 | 来源 | 必需 | 缺失时 |
|---|---|---|---|
| 素材原文 | 入口输入，见下面「第 0 步：素材形态判定」 | 是 | 停止并交回入口 |
| 类型编号与细分 | 入口输入（按 `../references/类型注册表.md` 选定；用户说「你帮我归」时，入口给的也是这个三元组） | 是 | 停止：类型不明不得派员 |
| 素材库根目录 | 入口输入 | 否 | 使用默认值 ./素材库/（相对当前工作目录） |

## 步骤

0. 判素材形态（F-18），分四类，各走各的路。**先判再采，不把截图当文字读、也不假装读得懂语音**：

   - **文字**：用户直接贴的文本。原样进第 1 步。
   - **截图／图片**：先看宿主能不能读图（能返回图片内容就说明能）。能读就认字，把认出的文字当「文字」走第 1 步，并在卡上「来源」里写明「截图识读」；读不出字（图太糊、是照片不是文字）时如实说读不出，请用户把文字贴过来——**不猜图里写了什么**。宿主不能读图时直说做不到，请用户改用文字，不绕过。
   - **链接**：先看宿主能不能抓网页正文。能抓就取正文当「文字」走第 1 步，并在卡上「出处链接」记原链接；抓不到正文时按判据 J-27 判，如实说抓不到，请用户把要收的那段贴过来，**不用标题和摘要凑一张卡**。宿主不能联网时直说做不到。

     判「抓到了正文」看的是**目标内容在不在手里**，不是请求成不成功。HTTP 200、页面能打开、标题能读到，这三件**各自都不能单独当成抓到了**：登录墙、付费墙、整页 JS 空壳、只返回摘要或「内容不存在」提示，都会让请求成功而正文为空。**判断方法是问自己：我要收的那一段，现在能不能逐字引出来？** 能，才算抓到；只能说出标题和大概意思，就是没抓到。平台提示「内容不存在」也不可尽信——可能是访问方式的问题（缺参数、被反爬），不一定是内容真的不存在；但**无论哪种，结论都一样：没拿到就请用户贴，不去猜**。
   - **语音／音视频**：宿主能转写就转成文字后走第 1 步，并在卡上「来源」里写明「语音转写」；不能转写时直说做不到，请用户改用文字。**不臆测语音内容**。

   四类都做不到时，统一一句「这个格式当前环境读不了，请把文字贴过来」，然后停下等用户，不降级成猜。

   无论从哪种形态来，产出的卡与纯文字卡**同格式**：版式不变、字段不变，只在「来源」或「出处链接」里留一句形态说明，方便日后回查原始出处。产出：可交给采集员的文字素材。

1. 按类型编号定位注册表行，确认大类、维度与落库路径。产出：本类型的采集参数，不落盘，内存传递。
2. 按大类派采集员，两件任务书一起交：`../agents/采集员通用.md`（共性契约）与 `../agents/<大类名>采集.md`（差异页，缺件即停止并交回入口）。产出：素材点列表。
3. 核对采集员返回的必需字段（类型编号、细分、素材点列表），缺任一不采信并重派。产出：可信素材点列表。
4. 按素材点分两路处理：先按 J-05 查重。查同一对象要用 `--object`：

   ```
   node scripts/vault.mjs find --object 五条悟
   ```

   它按「对象标识」认，不按字面——「五条悟」「五条 悟」「五条悟（咒术回战）」都算同一个对象（判据 J-23）。**不要只用 `--keyword` 查对象**：关键词只在卡名与要点里找字面包含，换个写法就查不到，于是第二次采集会建出第二张卡，而这正是 F-30 要断掉的事。`--keyword` 留给「找讲这类东西的卡」，`--object` 用来「看这个人/这部作品有没有卡」。

   需要收窄时可叠加 `--bucket`／`--family`／`--sub`，但**至少给一个筛选项，不要整表翻**——库上千张时翻不动，也看不出相关性。

   **落到库里统一走 `add`，不要直接 `write`：**

   ```
   node scripts/vault.mjs add --card <临时JSON>
   ```

   它自己判三件事，你不必先猜：

   - 同类型内没有这个对象 → 建新卡（`created`）
   - 同类型内已有、这次的内容它已经有了 → **不建卡**，告知已有（`skipped`）
   - 同类型内已有、有新内容 → 追加「日期＋补了什么」进旧卡的补充记录（`appended`），不建新卡

   三种都是退出码 0。只有参数不合法才是 2。跨类型时它正常建卡，并**自动把两边路径写进各自的「关联卡」行**——跨类型不算重复（同一个人物设定卡和作品切片卡是两回事），但两张卡得互指，否则写书时问这个对象只能拿到其中一张。

   只在一种情况下直接用 `write`：批量收编时已知全部是新卡、且已确认对象不重复（`collect` 流程里每批的剩余清单本身就是去重过的）。即便如此，拿不准就用 `add`，它多判一次不会出错。

   卡对象按 `../assets/素材卡版式.md` 组装：`basic`、`dimension`、`body` 三节加 `relPath`；`dimension` 按注册表该行动作列补行；`basic` 里要填「对象标识」（判重靠它）。大类、采集日期、关联卡等版式字段由本步骤补齐，采集员只交素材点。产出：待写入的卡对象与相对路径 `<大类>/<类型>/卡-<YYYYMMDD>-<短名>.md`。
5. 逐张落库并复述结果：把第 4 步得出的卡对象写成 JSON，存入临时文件，跑第 4 步给的 `add` 命令。它校验字段、补「私有」默认值、判是否补卡、落卡并同步改好索引，一次完成；退出码 1 表示卡未写入，按输出的问题改后重试。**把 `created`／`appended`／`skipped` 如实告诉用户**——尤其 `skipped`，用户要知道这次没进库是因为已经有这张卡了，不是漏采。产出：素材卡文件与更新后的 INDEX.md。

## 产出

素材卡文件与更新后的 INDEX.md，路径规则见第 4、5 步。

## 停止条件

- 当采集员两次返回都缺必需字段时，停止并交回入口。
- 当用户新说的细分与注册表冲突时，以用户口径为准产卡，冲突记入卡片备注，不停止。
- 当第 0 步判定宿主读不了这种形态（读不了图、抓不到正文、转写不了语音）时，停止并如实说做不到，请用户改用文字；不猜内容、不拿标题摘要凑卡。
- 当截图读得出但认不出字、链接抓回来是空壳时，停止并请用户把文字贴过来，不虚构。
