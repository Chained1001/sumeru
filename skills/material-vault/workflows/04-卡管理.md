# 04 卡管理

所属技能：material-vault。入口见 `../SKILL.md`。

## 目的

把用户对已有素材卡的改动需求（改一处、删掉、并进另一张、挪类型、记一笔用在第几章、看哪些该退休、查同对象双卡）落到卡与索引上，一次一个动作，做完索引与卡一致。

## 输入

| 字段 | 来源 | 必需 | 缺失时 |
|---|---|---|---|
| 操作意图 | 入口输入（改／删／找回／合并／挪类型／记已用／看退休） | 是 | 停止并交回入口 |
| 目标卡 | 用户给的路径，或用户给的卡名／要点（由第 1 步在 INDEX.md 里找） | 是；`retire` 不需要 | 按第 1 步找不到时，请用户给出卡的相对路径，不猜 |
| 作品与章节 | 入口输入（`used` 用） | `used` 时是 | 停下问清楚，不自己编一个书名或章号 |
| 新值或目的位置 | 入口输入（`edit` 的新值、`move` 的桶与类型族、`merge` 的目标卡） | 视动作而定 | 该动作需要却没有时，停下问清楚再动手 |
| 素材库根目录 | 入口输入 | 否 | 使用默认值 ./素材库/（相对当前工作目录） |

## 步骤

1. 读 <库根>/INDEX.md，按用户给的卡名或要点找行，取出该行的「相对路径」；用户直接给了路径时跳过查找。产出：目标卡的相对路径（一个或多个）。找不到、或一张卡名对上好几行时，把候选列给用户挑，不自行认定。
2. 判意图，选子命令：用户说「写错了／改一下／要点改短」走 `card edit`；说「删掉／不要了」走 `card delete`；说「并进那张／合成一张」走 `card merge`；说「归错了／挪到剧情桥段／换个类型」走 `card move`；说「上次删的那张找回来」走 `card restore`；说「这个桥段我用过没／记一笔用在第几章」走 `used`；说「哪些卡该退休了／有没有用不上的卡」走 `retire`。产出：本次操作的动作与参数。

   `retire` 与 `used` 是这一版新增的两件事，与改删不同：
   - `retire` 只列建议清单，**不删任何卡**。清单里的卡要不要退休由用户拍板——机器判的只是「三个月没动过」，判不了「这张卡好不好」。用户看完说要删，才逐张走 `card delete`。
   - `used` 记的是「这张卡被用进哪部作品的第几章」，形如「《长夜》第 12 章」。多部作品追加而不覆盖：覆盖会抹掉前一次的记录，而记这条记录的目的正是「防同一个梗用两遍」。
3. 动作前先把改动点说给用户核：`edit` 说清改哪一行、改成什么；`merge` 说清哪张并进哪张，以及两卡现有的补充记录与关联卡都会保留；`delete` 说清卡名，并说明卡会进 `已删卡片/`、之后可用 `restore` 找回。产出：用户确认。
4. 执行单个子命令，一次只做一个动作，不在一句命令里连做多件。参数与动作的对应见下表。产出：退出码与脚本报告的新路径或问题清单。

   | 动作 | 命令 |
   |---|---|
   | 改字段 | `node scripts/vault.mjs card edit --vault <库根> --path <相对路径> --field <字段名> --value <新值>` |
   | 改类型维度节的字段 | `node scripts/vault.mjs card edit --vault <库根> --path <相对路径> --field <维度名> --value <新值> --section 类型维度` |
   | 删卡 | `node scripts/vault.mjs card delete --vault <库根> --path <相对路径>` |
   | 找回删掉的卡 | `node scripts/vault.mjs card restore --vault <库根> --path <相对路径>` |
   | 合并 | `node scripts/vault.mjs card merge --vault <库根> --from <被并入的卡> --into <目标卡>` |
   | 挪类型 | `node scripts/vault.mjs card move --vault <库根> --path <相对路径> --bucket <桶> --family <S-NN 族名>` |
   | 记已用 | `node scripts/vault.mjs used --vault <库根> --path <相对路径> --work <书名> --chapter <章>` |
   | 看哪些该退休 | `node scripts/vault.mjs retire --vault <库根>`（可加 `--months <月数>` 调闲置线，默认 12） |
   | 查同对象双卡 | `node scripts/vault.mjs dupes --vault <库根>` |

   退出码 1 表示业务失败（卡不存在、新路径已存在、原位置被占用等），按输出的那条问题处理，不改成手改文件绕过。

   用户问「库里有重复的卡吗／同一个人是不是建了两张」时走 `dupes`。它按「类型族＋对象键」分组，**只列不改**；输出会给出一条 `card merge` 命令作参考，但仍要按第 3 步把「哪张并进哪张」说给用户核。两件事不许省：

   - **跨类型不算重复**：同一个人在「人物设定」与「作品切片」里各一张是对的，`dupes` 不会把它们列成双卡。
   - **机器判不出哪张写得更好**：它只按采集日期建议留下较早那张。两张内容不同时，要逐张看过再决定并哪张，不能照着默认值自动执行。
5. 跑 `node scripts/vault.mjs check --vault <库根>` 复核，退出码 0 才向用户报完成；退出码 1 时按问题清单改，不宣布完成。产出：改后的卡与一致的 INDEX.md。

## 产出

改后的卡与更新后的 INDEX.md；`delete` 与 `merge` 另在 `<库根>/已删卡片/` 下留一份按原相对路径存放的卡，可用 `card restore` 找回。`retire` 与 `dupes` 不改任何文件，只在对话里给一份清单。所有写操作都由脚本读写卡与索引，本流程不手改任何文件，也不手改 INDEX.md。

## 停止条件

- 当 INDEX.md 里找不到目标卡，或卡名对上个多行分不清是哪张时，停止并请用户给相对路径。
- 当用户要改的是「桶」或「类型族」时，不停止，改用 `card move` 一步做，不拆成「先改字段再搬文件」。
- 当 `restore` 报原位置已被占用时，停止并说明占用情况，由用户决定是删掉占用它的卡还是改名；不覆盖。
- 当 `check` 仍报错时，停止并交回问题清单，不继续做下一个动作。
- 当用户说「这些退休的都删了吧」时，不停止，但**逐张确认**、每张走一次 `card delete`，不写一句循环批量删；`retire` 的清单只是建议，删哪张得用户点名。
- 当 `dupes` 列出双卡、而用户说「都合了吧」时，不停止，但**逐组确认**：每组先说清哪张并进哪张、两卡各写了什么；内容不一样时要提醒用户机器判不出哪张更好。
- 当 `dupes` 列出的是跨类型的同一对象时，不停止也不合并：跨类型各自成卡是对的，改用 `card edit` 把路径填进两张卡的「关联卡」行。
- 当用户要求 `used` 却不记得书名或章号时，停止并请他补上；不填「某书」「未知章」这类占位值，那等于没记。
