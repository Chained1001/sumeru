# 03 检索

所属技能：material-vault。入口见 `../SKILL.md`。

## 目的

按写作需求路由到对应类型，从素材库筛出可用素材，输出带出处的引用清单。

## 输入

| 字段 | 来源 | 必需 | 缺失时 |
|---|---|---|---|
| 写作需求 | 入口输入 | 是 | 停止并交回入口 |
| 类型编号 | 入口输入（按 `../references/类型注册表.md` 从需求推导，用户可纠正） | 否 | 全库检索 |
| 素材库根目录 | 入口输入 | 否 | 使用默认值 ./素材库/（相对当前工作目录） |

## 步骤

1. 先收窄再比对（F-19）：把写作需求拆成「大类／类型／细分／关键词」四级筛选项，跑 `node scripts/vault.mjs find --bucket <大类> --family <类型> --sub <细分> --keyword <词>`（选项按需给，至少给一个）。它只在 INDEX.md 的行上筛，不打开卡正文；输出为命中的卡名、要点与相对路径。不要在 INDEX.md 上整表翻——库上千张时翻不动，也看不出相关性。产出：候选卡路径清单，不落盘，内存传递。

   需求横跨多个类型时，`--bucket` 与 `--family` 可以一次给多个值（逗号分隔，全角逗号也认），**不要拆成跑好几遍**：

   ```
   node scripts/vault.mjs find --bucket 故事零件,现实避坑 --family "S-03,S-04,S-05,S-10" --keyword 诏狱
   ```

   「主角进诏狱」这类需求天生横跨历史细节、桥段、意象、避雷（F-25），一个一个类型去查等于把「一句话查多类型」推回给用户。多值在同级内是「或」的关系（命中任一个就算），不同级之间仍是「与」。命中多类型时输出会按类型分组，正好看出哪一个类型有料、哪一个类型空着——**空着的那类型要如实说没查到，不要用别的类型的卡凑数**。`find` 会把「请求了但没有卡」的类型按「【S-04】0 张」列出来，不必自己记问过哪些类型——照它报的转述即可。

2. 判相关性，**分两趟，不要一上来就逐张打开卡**：

   1. **先在索引上粗筛**：`find` 回来的每一行已经带了 40 字以内的「要点」，够剔掉明显不相关的。这一趟只看索引行，**不打开卡、不读正文**。
   2. **再逐张打开剩下的卡**，按判据 J-04 判定与需求的相关性，淘汰弱相关；时效敏感类型先看时效状态，已过时的热梗与时事降序排后并标注。

   粗筛后仍有**超过 20 张**时，不要闷头全读：按类型分组报出各组张数，问用户先看哪一个类型。理由是这个量级上一张卡正文几百字，20 张就是上万字全进上下文，而机器在候选这么多时判的相关性本来就不可靠——**让用户砍，比机器猜便宜**。

   产出：选中卡清单。
3. 组织回复，每条素材给要点、摘录或事实要点、卡路径，并写一句素材与需求的对应关系。产出：检索结果。

## 产出

检索结果，不落盘，内存传递后写入对话回复。

## 停止条件

- 当 <库根>/INDEX.md 不存在时，停止并交回入口。
- 当候选为 0 张时，先分清是哪一种，**两句话不能说成一句**：
  - **筛得太窄**：放宽一级筛选项再跑一次——去掉细分、去掉关键词，或把 `--family` 从多值收成一个。`find` 无命中时会把它实际用的收窄条件回给你，照那个放宽。放宽后有了就照常往下走。
  - **库里确实没有**：如实回复无匹配并建议先采集，不编造素材。
  - 判断依据不是感觉：先看库里总卡数与该类型的卡数（`overview` 一条命令给全），类型里有卡而筛出来是 0，就是筛窄了。
- 把两支混成「建议先采集」，会把库里有料、只是没筛到的用户赶去白建卡——而建卡的成本远高于放宽一次筛选。
