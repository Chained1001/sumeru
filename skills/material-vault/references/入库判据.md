# 入库判据

## 适用范围

采集流程与各采集员的切分、归类、查重与要点撰写，调研采集流程的原始发现采信，检索流程的相关性判定。

| J-21 | 项目视图按卡上「已用在」行筛，不另建引用记录；书名带不带书名号都算同一本；一本书没记过「已用在」时如实说还没用过，不说成「库里没有这张卡」 | 硬 | 机器：`vault.mjs project --work <书名>` 输出该书用过的卡；人工：空清单时是否被说成库缺料 | E-11 |
| J-22 | 引用包（及任何导出产物）一律排除「私有：是」的卡，无开关可绕；被排除的卡要在结果里报出来；全是私有卡时报错、不产出空文件；不导出「已用在」「补充记录」「关联卡」三行 | 硬 | 机器：`vault.mjs pack` 过滤并在输出里列 excluded；人工：产物里是否出现私有卡的卡名或内容 | E-13 |
| J-23 | 「同一对象」按对象标识判定，不按字面：比对前去掉空白、括号注释与书名号，全角转半角，英文转小写；不做拼音或编辑距离的模糊匹配（误并两张该分开的卡比漏判更难挽回）。卡上没有「对象标识」时由卡名推 | 硬 | 机器：`cardFormat.mjs` 的 `objectKey`／`objectKeyOf`，`vault.mjs find --object` | E-14 |
| J-24 | 再积累同一对象：同类型内已有卡且内容已含 → 不建卡并告知已有（退出码 0）；有新内容 → 追加「日期＋补了什么」进旧卡补充记录，不建新卡（内容本身自带日期时原样写，不再叠采集日）；同对象但跨类型 → 各自成卡，并自动把两边路径写进各自的「关联卡」行（跨类型不算重复，单向填则从旧卡查不到新卡） | 硬 | 机器：`vault.mjs add --card <JSON>` 的 action 三态（created／appended／skipped） | E-14 |
| J-25 | 查全库双卡按「类型＋对象键」分组，跨类型同对象不算双卡；只列不改，建议留下较早那张但标明「机器判不出哪张写得更好」 | 硬 | 机器：`vault.mjs dupes` 的分组与输出 | E-15 |
| J-26 | 「证实」有两种成立方式，二者都不靠数网址——(a) **两个互相独立的主体**分别给出；(b) **拿到事实的原始发布方本身**（颁奖机构、官方数据接口、政府部门原文、当事公司的公告、原始论文）。同稿转载、同一通讯社的电头、同一家的不同频道、数据库二次加工，都**不算独立的第二源**，也**不算一手源**。用户口述永远只算一源。多个媒体复述同一个错误仍是一个错误——循环印证不是交叉验证 | 硬 | 人工核对：记「证实」时须能说出是哪一种——是「两个不相关主体」还是「原始发布方本身」；说不出即降为「单源」；抽查佐证域的署名与电头，同源即降级 | E-17 |
| J-27 | 判「抓到了正文」看目标内容在不在手里，不看请求成不成功：HTTP 200、页面能打开、标题能读到，三者各自都不能单独作为抓到的依据。判断方法是「要收的那一段现在能不能逐字引出来」——只能说出标题与大概意思，就是没抓到。**没抓到之后怎么办，看是谁在抓**：主对话面向用户，按 `01-采集` 第 0 步请用户贴文字；子代理够不到用户，把这条降为「线索」或写进未覆盖面，**不得因为「反正只能记单源」就把它当正文入卡**——单源说的是「只有一个可信来源」，不是「内容没读到但来源可信」。平台提示「内容不存在」不可尽信，但无论真假，结论都是不猜 | 硬 | 人工核对：问「这段能不能逐字引出来」，答不出即判未抓到；卡上出现无原文支撑的正文即违规 | E-18 |
| J-28 | 收集一部作品的多维度素材时，每张卡都要在「出自作品」行写作品名（如「幻界战线」），把散在人设、世界设定、剧情桥段等不同类型的卡归拢起来；这一行记的是「这条料从哪来」，与「对象标识」（这张卡讲谁）不是一回事——同一个角色可能出现在多部作品里，而一部作品的几十张卡对象标识各不相同，只有「出自作品」能串起来。原创点子与现实见闻留空，不算漏填。多维度收集按 `按作品收集策略.md` 的七维清单走，默认先试采三张给用户看口径 | 硬 | 人工核对：`vault.mjs find --from-work <作品名>` 能否一次取出该作品跨类型的全部卡；抽查卡上「出自作品」行非空且与所属作品一致 | E-19 |
| J-29 | 榜单数据必须带齐四个元信息才算可信：**榜名**（哪个平台哪个榜）、**时点**（取数年月日）、**排序口径**（评分／热度／销量／平台加权）、**过滤条件**（最少评价人数、是否按作品去重）。名次与分数属「数据事实」，榜单页即原始发布方，可记「证实」（J-26 路径 b）；「为什么排这么高」属推断，必须标〔推断〕并写依据。同一作品的多版本与多卷要合并取最高分代表，但「前篇／后篇」这类独立上映的条目不算多形态，不合并 | 硬 | 人工核对：卡上四个元信息是否齐；抽查一条看名次与分数能否回到榜单页对上；有无把推断写成事实 | E-20 |
| J-30 | 卡点条目只写**可数或可指认的现象**，不写评价。「转场几处、各用什么承接」可判；「转场生不生硬」不可判，因为它把现象与读者反应焊在一起，两个人会各判一半然后互相矛盾。主语是「作者」的条目（卡文、起名难、想学某作品、简介文案）**不进卡点表的验证列**，单列为情境条目——它们永远无法用成品证伪，混进来会默认成立，把整张表的置信度抬虚 | 硬 | 人工核对：条目里有没有「生硬／刻意／不足／不落地／腻」这类评价词；有就把后半句拆掉 | E-21 |

来源等级取值口径：证实＝关键事实有两个独立主体的来源，或拿到原始发布方本身（见 J-26）；单源＝单一可信来源，或只有转载与二次加工佐证；线索＝待佐证；存疑＝链接不可达或仅摘要互证、未打开原文核对（检索排序最末）。
