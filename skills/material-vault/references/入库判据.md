# 入库判据

## 适用范围

采集流程与各采集员的切分、归类、查重与要点撰写，调研采集流程的原始发现采信，检索流程的相关性判定。

## 内容

判据类，每条一行：

| 编号 | 判据 | 强度 | 判定方法 | 依据 |
|---|---|---|---|---|
| J-01 | 一条素材点只含一个可单独引用的点 | 硬 | 人工核对：把素材点拆成两半，任一半单独被写作引用仍成立则拆分，否则合并 | E-01 |
| J-02 | 每张卡的桶与类型族恰好一对，且取值限于类型注册表 S-01 至 S-11；子类开放 | 硬 | 人工核对：卡的类型行与注册表逐字比对 | E-02 |
| J-03 | 卡的要点不超过 40 字，含标点 | 硬 | 计数：超 40 字即改写，不截断 | E-01 |
| J-04 | 素材与写作需求相关：能直接支撑需求场景，或换题材后可迁移 | 参考 | 模型判断：写出素材与需求的一句话对应关系才判相关，写不出即淘汰 | E-01 |
| J-05 | 同一对象在同类型族内只建一张主卡；再积累命中已有卡时，无新内容不建卡并告知用户已有卡，有新内容补进旧卡并在卡尾记补充行（日期＋补了什么） | 硬 | 人工核对：索引无同对象双卡；补充行与采集日期对应 | E-01 |
| J-06 | 时事热点与网络热梗的卡必填时效状态（现行、已过时、待观察），其余类型填长期 | 硬 | 人工核对：卡上时效行非空且取值合法 | E-02 |
| J-07 | 照例切片保持整段完整，不为凑维度拆碎；伏笔埋收清单、节奏样例、原型基底按 J-11 整存 | 硬 | 人工核对：切片正文与原片段段落一致 | E-02 |
| J-08 | 源料卡的事实要点与可改造方向分开两处写，不混 | 硬 | 人工核对：改造方向里不得出现无出处的事实断言 | E-02 |
| J-09 | 每张卡的来源等级必填，取值限于：证实、单源、线索、存疑；用户口述素材默认记单源 | 硬 | 人工核对：卡上来源等级行非空且取值合法 | E-04 |
| J-10 | 境外来源（来源域在境外）的卡必标「来源：境外」；口述来源无来源域，不标，原型对象是境外作品不改变来源属性 | 硬 | 人工核对：来源域非大陆域时卡上有标注 | E-04 |
| J-11 | 三类整存不拆：原型基底（整角色整作品一张整卡）、节奏样例（整段曲线一张卡）、伏笔埋收清单（按作品一张清单卡）；组件卡按需另拆并与整卡互设关联 | 硬 | 人工核对：整卡与组件卡的关联行互相指向 | E-04 |
| J-12 | 方法步骤、事实细节中，原文明说的标〔原文〕，据素材推断重构的标〔推断〕，不得混写 | 硬 | 人工核对：逐处检查标注与内容来源一致 | E-04 |
| J-13 | 每张卡的「私有」必填，取值限于：是、否；故事零件·开书点子（S-01）默认「是」，其余类型族默认「否」，调用方显式给定的以卡上取值为准 | 硬 | 机器判定：`cardFormat.mjs` 的 `checkBasic` 校验取值合法，`vault.mjs` 的 `writeCard` 补默认值 | E-06 |
| J-14 | 「原文摘录或事实要点」行的摘录部分不超过 120 字；超了就只留最说明问题的一句，其余写成事实要点，不整段搬运 | 硬 | 计数：数该行引号内或〔原文〕标注后的字数，超 120 即改写 | E-07 |
| J-15 | 群聊、私信、对话类素材只留方法、结构与可迁移的写法，不留可辨认的对话原文与参与人身份；引用他人原话一律改写为概述 | 硬 | 人工核对：该行是否出现可辨认的第三方原话或昵称，出现即改写 | E-07 |
| J-16 | 退休只建议不执行：判据是「采集日期超过 12 个月，且『已用在』与『补充记录』都为空」；满足三条的进建议清单，删不删由人逐张点名 | 硬 | 机器：`vault.mjs retire` 按三条筛；人工：清单出来后逐张确认才 `card delete` | E-08 |
| J-17 | 已用标记记到「《书名》第 N 章」，多部作品用「；」追加，不覆盖前一次；记不出书名或章号时留空，不填「某书」「未知章」这类占位值 | 硬 | 检查该行是否形如「《…》第 … 章」；出现「某书」「未知」「待补」即视为未记 | E-08 |
| J-18 | 复审按子类分档算周期：网络热梗 3 个月、时事热点 6 个月、其余时效敏感 12 个月；时效状态为「长期」的卡不入复审清单。带出处链接的卡只提示「久未核对」，不得声称链接已失效——本技能离线可用，未做过任何链接探测 | 硬 | 机器：`vault.mjs review` 按子类取周期；人工：该输出里出现「已失效」即违规 | E-09 |
| J-19 | 库况的「待补」只数 F-10 定义的占位值（升级时机器补不出、填成「待补」的必填字段），不把缺内容或想法未定的卡算作待补；「偏薄」只作提示、不当错误，薄线默认 5 张 | 硬 | 机器：`vault.mjs overview` 数各卡必填字段值等于「待补」的处数 | E-09 |
| J-20 | 一句话查多族：需求横跨多族时，`--bucket` 与 `--family` 一次给多个值，不拆成多遍查；同级多值取「或」，隔级取「与」；查询结果里空着的那一族要如实说没查到，不拿别族的卡凑数 | 硬 | 机器：`vault.mjs find` 接受逗号分隔的多值并按族分组输出；人工：回复里是否为空族编了内容 | E-11 |
| J-21 | 项目视图按卡上「已用在」行筛，不另建引用记录；书名带不带书名号都算同一本；一本书没记过「已用在」时如实说还没用过，不说成「库里没有这张卡」 | 硬 | 机器：`vault.mjs project --work <书名>` 输出该书用过的卡；人工：空清单时是否被说成库缺料 | E-11 |
| J-22 | 引用包（及任何导出产物）一律排除「私有：是」的卡，无开关可绕；被排除的卡要在结果里报出来；全是私有卡时报错、不产出空文件；不导出「已用在」「补充记录」「关联卡」三行 | 硬 | 机器：`vault.mjs pack` 过滤并在输出里列 excluded；人工：产物里是否出现私有卡的卡名或内容 | E-13 |
| J-23 | 「同一对象」按对象标识判定，不按字面：比对前去掉空白、括号注释与书名号，全角转半角，英文转小写；不做拼音或编辑距离的模糊匹配（误并两张该分开的卡比漏判更难挽回）。卡上没有「对象标识」时由卡名推 | 硬 | 机器：`cardFormat.mjs` 的 `objectKey`／`objectKeyOf`，`vault.mjs find --object` | E-14 |

来源等级取值口径：证实＝关键事实双源一致；单源＝单一可信来源；线索＝待佐证；存疑＝链接不可达或仅摘要互证、未打开原文核对（检索排序最末）。
