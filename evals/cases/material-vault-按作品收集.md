# material-vault 按作品收集

## 输入

- 被测技能：skills/material-vault
- 指令：`帮我收集幻界战线`
- 样本：不提供（本用例要测的正是「只给作品名、不给具体收什么」时的默认规划）
- 运行方式：人工对话
- 前置状态：`素材库/` 已建（`vault.mjs init`），INDEX.md 只有表头，0 张卡

选题的理由：这是唯一一条「用户一次说出一部作品的多个方面」的路径。它最容易退化成两种错法——要么退回「两问定一个类型」逐类问一遍，要么一口气把七个维度全铺开、不经确认就产出几十张卡。

## 基线

- 基线版本：0.9.0（`references/按作品收集策略.md` 建立时的版本）
- 基线表现：2026-10-25 用同一部作品试采过三张（人设、世界设定、剧情桥段），落入三个类型，`find --from-work` 一次取回，`check` 通过。该次试采由开发者在对话里手工驱动，**未走过「用户只给作品名、技能自行规划」这条入口**，故本用例此前无基线。

## 期望

- 不退回两问逐类询问，而按七维清单给出本次要收的范围（人设、世界设定、剧情桥段、金句、意象氛围、起名、作品切片）。
- 默认只试采三张：结构类三类型各一张，来自三个不同的类型，不是同一类型三张。
- 试采后停下，把三张的口径给用户看，未经认可不铺开剩下四维。
- 每张卡的「出自作品」行写同一个作品名，且该行非空。
- 收的内容是可复用零件，不是剧情摘要：每张卡都能回答「可以搬到自己的哪个故事里」。
- `find --from-work <作品名>` 一次返回该作品跨类型的全部卡。
- `check` 退出码 0。

## 判据

| 编号 | 类型 | 判定条件 | 判定方法 | 证据位置 |
|---|---|---|---|---|
| C-01 | 硬性 | 收到「收集某作品」后按七维清单给出本次范围，没有退回「第一问选大类、第二问选类型」逐类询问 | 人工核对：对话记录里是否出现了七维范围说明，以及是否出现了两问式追问 | 对话记录 |
| C-02 | 硬性 | 默认只试采三张，且三张分属结构类三个不同类型（S-02 人设、S-04 世界设定、S-03 剧情桥段），不是同类型三张 | 计数：数试采卡的张数与「类型」值，去重后应为 3 个类型 | 卡文件与对话记录 |
| C-03 | 硬性 | 每张卡「出自作品」行非空，且全部是同一个作品名 | 计数：逐卡读「出自作品」行，比对是否一致 | 卡文件 |
| C-04 | 硬性 | `find --from-work <作品名>` 一次返回该作品跨类型的全部卡，不需分类型跑多次 | 命令：`node scripts/vault.mjs find --vault 素材库 --from-work <作品名>` | 命令输出 |
| C-05 | 硬性 | 试采三张后停下给用户看口径（分类对不对、要点是不是他要的、有没有该拆没拆），未经认可没有继续铺开剩下四维 | 人工核对：三张之后是否有一轮确认，以及确认前是否又新增了卡 | 对话记录与 INDEX.md 行数 |
| C-06 | 硬性 | 收的是可复用零件而非剧情摘要：抽查三张卡的「可迁移点」或「内容」，每张都能回答「可以搬到自己的哪个故事里」 | 人工核对：逐张读，答不出即不通过 | 卡文件 |
| C-07 | 参考 | 未覆盖面写明了本次没收到哪几维，标题式套话不算 | 人工核对：该字段是否点名了具体维度 | 对话记录 |
| C-08 | 硬性 | 全部动作结束后 `vault.mjs check` 退出码为 0 | 命令：`node scripts/vault.mjs check --vault 素材库` | `check` 输出 |

类型只有两种：硬性不通过即用例不通过；参考不通过只记录，不改变用例结论。
`C-` 是评测判据，与技能 `references/` 的 `J-` 不共用号段。编号从 01 起连续，一条判据只判一件事。

## 覆盖

| 覆盖步骤 | 覆盖判据 |
|---|---|
| 策略「一条硬约束：收的是零件，不是作品档案」 | C-06 |
| 策略「维度清单（七维）」 | C-01、C-02 |
| 策略「默认动作：先试采三张」 | C-02、C-05 |
| 策略「卡上要填『出自作品』」（判据 J-28） | C-03、C-04 |
| 策略「收全的判定」 | C-07 |
| 产卡后的一致性 | C-08 |

未覆盖：「先结构后文字」的顺序（要收满七维才看得出，本用例只到试采三张）；「一部作品固定用一个名字」（别名混用是数据问题，由 `test/vault-cli.test.mjs` 的 `find --from-work` 归一化测试钉住）；「文字类取不到原文时降线索」需真实缺失文本的场合，另立用例。
