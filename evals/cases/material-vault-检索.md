# material-vault 检索

## 输入

- 被测技能：skills/material-vault
- 指令：连续三句——
  1. `我写到主角被诬下狱，库里有什么能用的`
  2. `那有没有写唐朝长安西市胡商的`
  3. `第 3 张卡的摘录念给我听`
- 样本：内联在指令中
- 运行方式：人工对话
- 前置状态：`素材库/` 已建，用 `add` 建五张卡（采集日期各不相同）：
  - `故事零件/剧情桥段/卡-20261022-牢里开局.md`，要点含「开局」
  - `故事零件/剧情桥段/卡-20261025-越狱反转.md`，要点含「反转」
  - `故事零件/意象氛围/卡-20261023-雨夜铁窗.md`，要点含「雨夜」
  - `写作方法/金句语料/卡-20261021-绝境句式.md`，要点含「绝境」
  - `现实避坑/现实见闻/卡-20261024-明清诏狱实物.md`，要点含「诏狱」
  - 六张里刻意不放「世界设定」族的卡，用来测空族

选题的理由：第一句天生横跨四族（剧情桥段、意象氛围、金句语料、现实见闻），正好测「一句话查多族」；缺的那一族（世界设定）用来测空族会不会被别的族凑数；第二句库里有卡但筛不到，用来测「筛得太窄」与「库里确实没有」会不会被混成一句「建议先采集」。

## 基线

- 基线版本：0.10.1（`03-检索.md` 修订前的版本）
- 基线表现：停止条件只写「候选为 0 张时，如实回复无匹配并建议先采集」。而 `find` 无命中时自己会说「库里可能确实没有，也可能筛得太窄，可放宽再试」——**流程与脚本对同一件事给两种说法**。照流程读，第二句会被答成「建议先采集」，用户库里明明有五张卡却被告知去建卡。

## 期望

- 第一句拆成四级筛选项跑 `find`，`--bucket` 与 `--family` 一次给多值，不拆成跑四遍。
- 命中四族，输出按族分组；缺的「世界设定」这一族如实说没查到，不拿别的族的卡顶上。
- 每条素材给要点、摘录或事实要点、卡路径，并写出一句「素材与需求的对应关系」；写不出对应关系的淘汰。
- 第二句命中 0 张：先判断是筛得太窄还是库里确实没有，给出「放宽筛选」而非直接「建议先采集」。
- 第三句（要摘录）正常给出，因为检索流程本来就允许读卡正文——与浏览流程不同，浏览流程会把这句交回 03。
- 三句全程不写任何文件，`check` 退出码前后一致为 0。

## 判据

| 编号 | 类型 | 判定条件 | 判定方法 | 证据位置 |
|---|---|---|---|---|
| C-01 | 硬性 | 第一句把需求拆成筛选项后跑 `find`，没有整表翻索引（回复里能看出用了哪几级筛选项，或对话记录里有 `find` 命令） | 人工核对：对话记录里是否有带筛选项的 `find` 调用 | 对话记录 |
| C-02 | 硬性 | 横跨多族的需求一次给多值（`--bucket`／`--family` 逗号分隔），没有按族拆成跑好几遍 | 计数：数 `find` 被调用的次数与每次给的值 | 对话记录 |
| C-03 | 硬性 | 命中多族时按族分组呈现，缺的「世界设定」一族被如实说没查到，回复里没有把别的族的卡算进这一族 | 人工核对：分组是否出现，空族是否被点名说出 | 对话记录 |
| C-04 | 硬性 | 第二句命中 0 张时，先区分「筛得太窄」与「库里确实没有」并给出不同去处（放宽筛选 / 建议采集），没有一律答「建议先采集」 | 人工核对：回复落在哪一支，以及是否给了放宽的方向 | 对话记录 |
| C-05 | 硬性 | 每条入选素材都给了要点、摘录或事实要点、卡路径三项，且有一句「素材与需求的对应关系」 | 计数：逐条数四项是否齐 | 对话记录 |
| C-06 | 硬性 | 时效敏感类型（时事热点、网络热梗）先看时效状态；已过时的降序排后并标注。本库无此类卡时，本条以「未触发」记录，不改判 | 人工核对：有则看排序与标注，无则记「未触发」 | 对话记录与卡文件 |
| C-07 | 硬性 | 三句全程没有新建或修改任何文件 | 计数：对话前后各记一次 `check` 退出码与 INDEX.md、卡的 mtime | `check` 输出与文件 mtime |
| C-08 | 参考 | 说得出本次淘汰了哪些候选、凭什么淘汰（J-04 写不出对应关系即淘汰），不是把候选全收 | 人工核对：回复里有无淘汰说明 | 对话记录 |
| C-09 | 硬性 | 候选多时先用索引的「要点」粗筛（不打开卡），粗筛后仍超过 20 张时按族报出各组张数并问用户先看哪一族，没有逐张打开全部候选 | 人工核对：粗筛阶段是否出现读卡正文的动作；候选超量时是否把选择权交回用户 | 对话记录 |

类型只有两种：硬性不通过即用例不通过；参考不通过只记录，不改变用例结论。
`C-` 是评测判据，与技能 `references/` 的 `J-` 不共用号段。编号从 01 起连续，一条判据只判一件事。
