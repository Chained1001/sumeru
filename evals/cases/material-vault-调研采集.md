# material-vault 调研采集

## 输入

- 被测技能：skills/material-vault
- 指令：`帮我调研一下 2026 年诺贝尔文学奖得主，收进素材库`
- 样本：不提供（本用例要测的正是「只有主题没有素材」时的取材能力）
- 运行方式：人工对话
- 前置状态：`素材库/` 已建（`vault.mjs init`），INDEX.md 只有表头，0 张卡

选题的理由：诺奖公布后，中文媒体大量转载同一篇通稿。这是「看着是双源、其实是一源」最容易发生的场景，用来测「双源一致」的判定是否被转载骗过去。

## 基线

- 基线版本：0.8.0（`workflows/02-调研采集.md` 自建立以来从未有人跑过，无历史基线；本条由 2026-10-24 首次运行建立）
- 基线表现（实跑，结果如下），暴露三处：

  **① 「证实」只数来源域，不看主体 —— 已由 J-26 修。** 调研员把「诺奖官方接口 + 澎湃 + 搜狐」记为「证实」。这个结论**恰好是对的，但理由写错了**：它把三个来源域并列当成了三个证据，而澎湃与搜狐都是同一场发布会通稿的转述，真正独立的只有瑞典学院一家。判对是运气——同一条规则下次遇到「只有转载、没有官方接口」就会判错。

  初版 J-26 又矫枉过正：只写「两源须不同主体」，照字面读会让「只拿到官方接口」也降成单源——而官方接口恰恰是最硬的一手源。修法是改成两条路：(a) 两个互相独立的主体；(b) 拿到原始发布方本身。

  **C-05 也随之改写过一次**：它原写「中文报道均出自同一通稿 ⇒ 记单源」，照字面读会把本次「拿到官方接口」的正确结论判成不通过。用例判据与判据表各写各的，正是 Q6=(B) 选「先跑用例」要防的事。

  **② 官方页面 HTTP 200 但正文读不出 —— 已由 J-27 修。** `nobelprize.org` 的 summary、press-release 页全部返回 200，正文却被截断成标题一行。若没有 J-27，调研员完全可以拿标题当「读到了」，那一整份结果的证据强度会虚假地高。实际做法是正确的：改用官方 JSON 接口取证，并把「官方新闻稿正文未逐句核对」写进未覆盖面。

  **③ 单通道坏掉被写成「检索失败即停」 —— 已修停止条件。** 本次 WebSearch 四次全部失败（报 `DeepSeek search has no API key for DEEPSEEK_API_KEY`），WebFetch 全程可用。旧停止条件写「检索连续失败 3 次时停止」，照字面读调研员早该停；真停下来就采不到任何料。现改为区分「完全无网」（停）与「单通道坏掉」（不停，改用还能用的通道，并把「本次没有关键词发现能力」如实写进过程记录与未覆盖面）。

  **本次也确认了它做对的四件事**（改动不应破坏）：丢弃自称「诺贝尔奖中文网站」却只有「加载中……」的 SEO 站（S-17）；把 Wikidata 驱动的数据库站列为辅助而不单独计级；发现 `site:` 限定检索返回完全无关结果后不据此采信任何条目；三条中译本的出版信息因文末自述「汇编自网络资料」而记「线索」并写明疑点。

## 期望

- 走 02，不直接在对话里搜完就写卡：先派调研员（`agents/调研采集.md`），拿到带来源等级的原始发现，再进 01 产卡。
- 调研员返回三件套齐全：原始发现列表、未覆盖面、过程记录；缺任一不采信。
- 每条原始发现都有：标题、事实要点、来源域、来源链接或出处、日期、来源等级。来源等级只取「证实、单源、线索、存疑」四值。
- 关键事实若只有一家原创、其余是转载，记「单源」；不给「证实」。
- 过程记录落 `辅助内容/临时文件/` 下的当日文件，不进素材库。
- 卡上「来源等级」与调研结论一致；卡上「出处链接」指向真正的原创来源，不指向转载页。
- 全程 `check` 退出码 0，索引与卡一致。

## 判据

| 编号 | 类型 | 判定条件 | 判定方法 | 证据位置 |
|---|---|---|---|---|
| C-01 | 硬性 | 走了 02 的分派路径，有一次明确的调研员调用，而不是主对话直接搜索后写卡 | 人工核对：对话记录中是否有调研子代理的结构化返回 | 对话记录 |
| C-02 | 硬性 | 调研员返回含原始发现列表、未覆盖面、过程记录三项；任何一项缺失时没有继续产卡 | 人工核对：三项是否齐备 | 对话记录 |
| C-03 | 硬性 | 每条原始发现的六个字段（标题、事实要点、来源域、来源链接或出处、日期、来源等级）都不为空 | 计数：逐条数六字段 | 对话记录 |
| C-04 | 硬性 | 来源等级取值只出现「证实、单源、线索、存疑」，无自造档位 | 人工核对：逐条比对取值集合 | 对话记录 |
| C-05 | 硬性 | 关键事实记「证实」时，必须能说出它凭的是哪一条：(a) 两个**互相独立**的主体分别给出，或 (b) 拿到了**原始发布方本身**（颁奖机构官网或官方数据接口、政府部门原文）。若中文报道全部出自同一篇通稿或同一通讯社，则**只有拿到原始发布方**才能记「证实」，其余一律「单源」 | 人工核对：抽查三条报道的署名与电头确认是否同源；再看该条记「证实」的理由落在 (a) 还是 (b)，说不出即判不通过 | 对话记录与来源页面 |
| C-06 | 硬性 | 卡的「出处链接」指向原创来源（颁奖机构官网或首发媒体），不指向转载页 | 人工核对：打开该链接确认 | 卡文件 |
| C-07 | 硬性 | 过程记录落在 `辅助内容/临时文件/` 下，素材库里不出现过程记录文件 | 计数：比对素材库文件清单 | 素材库目录与 `辅助内容/` |
| C-08 | 硬性 | 全部动作结束后 `vault.mjs check` 退出码为 0 | 命令：`node scripts/vault.mjs check --vault 素材库` | `check` 输出 |
| C-09 | 参考 | 未覆盖面写明本次没查到的方向（如获奖者生平细节、作品评价），全覆盖时写「无」 | 人工核对：该字段是否为空泛套话 | 对话记录 |
| C-10 | 硬性 | 没有「请求成功就算读到」的发现：凡是打进原始发现列表的事实，都要能指出它是从哪段可逐字引出的原文里来的；只能说出标题与大概意思的，必须落在「线索」或未覆盖面里，不得作为「单源／证实」的正文 | 人工核对：随机抽三条，问「这段原文能不能逐字引出来」，答不出即不通过；再查是否有条目只凭标题与摘要就记了单源 | 对话记录与来源页面 |

类型只有两种：硬性不通过即用例不通过；参考不通过只记录，不改变用例结论。
`C-` 是评测判据，与技能 `references/` 的 `J-` 不共用号段。编号从 01 起连续，一条判据只判一件事。
