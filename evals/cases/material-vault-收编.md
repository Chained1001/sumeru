# material-vault 收编

## 输入

- 被测技能：skills/material-vault
- 指令：`D:\散料 里是我攒的素材，都收进来`
- 样本：来源目录里 12 个 `.txt` + 1 张 `.png`
- 运行方式：人工对话
- 前置状态：`素材库/` 已建、0 张卡；来源目录建 13 个文件，其中**第 3 个 `.txt` 内容只有一行且无法产出合法卡**（用来测写失败怎么处理），第 13 个是 `.png`（用来测「不采」会不会被静默漏掉）

选题的理由：07 是唯一「批量」流程，它的错法都是**量变引发**的——试采被跳过就直接压 12 张、每批不记进度导致下次重采、写失败的文件被记进进度导致永久漏采。这三件事在单张卡上看不出来。

## 基线

- 基线版本：0.10.5（`07-收编.md` 补「失败不进进度」之前的版本，`evals/` 下此前没有收编用例）
- 基线表现：流程写「每批 10 个就落一次库并记一次进度」，也警告过「只记进度不写卡，进度就成了空头支票」，**但没写怎么防**。`collect mark --done` 只认文件名、不知道哪几张 write 失败，所以本批 10 个里第 3 个写失败时，进度照样把它记成「已采」——而下次续采只看进度，那张卡从此不会被重采，且没有任何提示。

### 机制验证（0.10.6，2026-10-26）

整条对话还没跑，但把两处机制先验了——这两处正是判据 C-02 与 C-06 依赖的前提，前提不成立时用例写得再对也跑不通。

**① `collect plan` 会不会漏掉不采的文件**（12 个 `.txt` + 1 个 `.png`）：

```
共 12 个可采的文本文件，另有 1 个不采（图片、音视频、认不出类型）｜源指纹 f63509a5ad97
...
不采的文件（要收请先转成文字）：
- 封面.png
```

C-02 的前提成立。

**② `collect mark` 能不能只传一部分文件**——这是 C-06 修法的地基。若 mark 只认整批，那「写失败的不传」就没法执行。

分批传 9 个（模拟第 3 个写失败、少传 m03）：

```
已记 9／12，剩 3 个待采
下次从这些接着采：
- m03.txt
- m11.txt
- m12.txt
```

m03 被正确留在待采里，下次会重采。**修法可执行。**

**③ 反例：照旧做法把失败项也传进去**

```
已记 10／12，剩 2 个待采     ← m03 被记成已采
库校验通过（0 张卡，格式版本 2）  ← 而库里一张卡都没有
```

**库里 0 张卡，进度却记了 10 个已采。** 这就是本文档自己警告的「只记进度不写卡，进度就成了空头支票」——warning 写在文档里防不住，必须落到「哪几个文件能进 `--done`」这个动作上。

## 期望

- 先问策略：全收还是按主题抽、要不要先试采几张，**两问一次问完**，不逐条挤牙膏；用户不答时按默认先试采 5 张。
- 先清点来源目录，把不能采的文件（图片、音视频）列进「不采」并说明它们要单独走 01，不静默跳过。
- 试采阶段**不写库**：试采完库里仍是 0 张卡，卡只在对话里列出清单。
- 试采后停下给用户看口径（分类对不对、要点是不是他要的、有没有该拆没拆），未经确认不开始全量。
- 全量按批走，每批 10 个落一次库并记一次进度，不是全部攒到最后一次性记。
- 写失败的文件**不进** `collect mark` 的 `--done`；失败清单在收尾时报给用户，并说明哪几个文件没进来。
- 进度数字取自 `collect mark` 的输出原样转述，不自己算。
- 收尾 `check` 退出码 0 且失败清单为空，才宣布收编完成。

| C-06 | 硬性 | 内容无法产出合法卡的那个文件，`write` 退 1 后**没有被传进 `collect mark` 的 `--done`**；收尾时失败清单点明了它是哪个文件 | 人工核对：比对 `--done` 的文件列表与 `write` 退 1 的文件；看收尾是否点名 | 对话记录与 `.收编进度/<指纹>.json` |
| C-07 | 硬性 | 报给用户的「已记 X／共 N」与 `collect mark` 的输出一致，没有自己算 | 人工核对：逐次比对 | 对话记录 |
| C-08 | 硬性 | 收尾 `check` 退出码为 0；失败清单不为空时不宣布收编完成 | 命令与人工核对 | `check` 输出与对话记录 |
| C-09 | 参考 | 用户中途喊停时能停在这一批的边界，并把 `mark` 报的剩余清单原样给出来 | 人工核对：停的位置与剩余清单 | 对话记录 |

类型只有两种：硬性不通过即用例不通过；参考不通过只记录，不改变用例结论。
`C-` 是评测判据，与技能 `references/` 的 `J-` 不共用号段。编号从 01 起连续，一条判据只判一件事。
