# 00 总则

本文件定义基座的适用范围、原则和事实源。其余十份标准以本文件为前提。

## 适用范围

基座适用于由它派生的每个项目。每个项目是一个独立的 GitHub 仓库，交付物是一个或多个 Agent Skills 文件夹，通过 `npx skills add` 安装。

基座的完整结构见上游的 `框架树.md`，它不随项目复制。标准只定规则，不重复结构描述。

## 按需查阅

十份标准不是一次读完的清单。按当前要做的事，只读下表对应的那一份。

| 要做的事 | 读哪份 |
|---|---|
| 新建或改技能、拆流程、写参考件或版式 | `01-技能写法.md` |
| 写脚本、加测试、定退出码 | `02-脚本与测试.md` |
| 起名、编号 | `03-命名.md` |
| 提交、开分支 | `04-提交与分支.md` |
| 改版本号、发版、写 CHANGELOG | `05-版本与发版.md` |
| 写或改文档 | `06-文档写作.md` |
| 加子代理 | `07-Agent 设计.md` |
| 收录素材、定许可证 | `08-许可证与素材.md` |
| 从基座派生新项目 | `09-项目派生.md` |
| 用 AI 施工：派子代理、写派单、审查、打回 | `10-施工流程.md` |

本文件只在两种情况下读：判断两份标准冲突时以谁为准；判断某个事实该写在哪。

一份都不适用时，不必读。

## 原则

1. 格式以开放标准为准。`SKILL.md` 遵循 agentskills.io 规范，不另造格式。宿主扩展键 `whenToUse`、`disable-model-invocation`、`user-invocable` 是登记过的受控偏差，不是另造格式，取值见 `01-技能写法.md` 的 frontmatter 节。
2. `skills/` 只放发布内容。技能可自带 `scripts/`、`references/`、`assets/`、`agents/`（结构见框架树）；示例、仓库级测试与 `docs/` 不进入 `skills/`。
3. 能用脚本检查的规则由脚本检查，模型只做语义判断。
4. 文档与交付物分开。`docs/` 是给人看的文档，技能的运行时流程不依赖它。

## 事实源

同一个事实只能有一个事实源，其他位置只写指针，不复写数值或结论。

- 项目内的事实以代码或可运行的检查为准。文档与代码冲突时，改文档。
- 框架标准本身没有代码，不适用上一条。框架标准之间冲突时，以本文件为准，并在相关标准中修正。
- 不能确定哪处是事实源时，不得默认采用其中一处。须先裁决，并在项目 `AGENTS.md` 的事实源节中登记。

## 源头与副本

- 标准的源头是 `开发框架/规范/`，模板的源头是 `开发框架/模板/`。只在这两处修改。
- 基座的 `docs/规范/` 与 `templates/` 是副本。它们随基座复制到每个项目，不在项目内修改。
- 修改源头后，同次把改动同步到副本。`test/standards.test.mjs` 与 `test/templates.test.mjs` 检查两边逐字一致，不一致则失败。

## 变更

- 标准的修改记录写在 `CHANGELOG.md` 的 `[Unreleased]` 段，标准文件中不留变更日志（见 06 的「变更」节）。
- 修改标准的可观察行为（如命名规则、退出码）时，同次更新测试与所在目录的说明。
