# 04 提交与分支

本文件规定提交信息与分支的写法。

## 提交信息

采用 Conventional Commits：

```
<类型>[(范围)][!]: <描述>

<正文，可选>

<脚注，可选>
```

- 类型只用英文：`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`。
- 范围可选，写被改动的目录或技能名。
- 描述用中文，不超过 50 字，不加句号。正文与描述之间空一行。
- 正文说明为什么改，不复述改了什么。
- 破坏兼容的改动在类型后加 `!`，如 `feat!: 改输出格式`；或在脚注写 `BREAKING CHANGE: <说明>`。两者用其一即可，同时用不冲突。
- 脚注每行一条，形如 `Refs: #12`、`Reviewed-by: <人>`。脚注与正文之间空一行。

## 分支

- `main` 为可发布状态，只通过合并进入。
- 每项工作一个分支，名称为 `类型/简述`，如 `feat/add-init-skill`。
- 合并后删除分支。

## 提交粒度

- 一次提交只做一件事。
- 改动规范或模板时，规范、模板、副本和测试在同一次提交中完成，避免分叉。

## 提交前

- 运行 `npm run validate` 与 `npm test`，两者都通过。
- 确认工作区没有临时文件。

## 变更

修改本文件，同次在 `CHANGELOG.md` 的 `[Unreleased]` 段记录。
