# sumeru 技术文档

| 字段 | 值 |
|---|---|
| 状态 | 草案 |
| 版本 | v1 |
| 最后更新 | 2026-10-24 |

本文件写给要改这个项目的人。读完应当能判断：代码怎么分层、数据怎么流、出错怎么处理、哪些决定不能随便推翻。

产品口径（做什么、做到什么程度）在 `docs/产品/PRD.md`；本文件只写实现边界与取舍，两者冲突时以 PRD 定需求、以 `docs/规范/` 定规则。

## 目标与约束

| 类型 | 内容 | 判据或原因 |
|---|---|---|
| 质量目标 | 静态校验与测试全绿 | `npm run validate` 与 `npm test` 退出码均 0；跳过项只允许设计内的两类（副本比对、受限环境 CLI） |
| 质量目标 | 千卡库单次校验不超过 2 秒 | `node scripts/vault.mjs check --vault <库根>` 计时，未测，由人在建到 1000 张卡后核 |
| 质量目标 | 老库一条命令升到当前格式 | 造格式第 1 版的库跑 upgrade 后 `check` 退出码 0，且重跑不产生二次改动 |
| 质量目标 | 零依赖 | `package.json` 不含 `dependencies` 与 `devDependencies`，脚本只 import `node:` |
| 约束 | 交付物只有 `skills/` 一个目录 | 技能经 `npx skills add` 安装，仓库级文件不会到达使用者 |
| 约束 | 素材原文不进库 | 公开仓库，收入整段原文即侵权，且与用户的原文目录形成双源 |
| 约束 | 卡格式加减字段，同次改版式、判据、升级器 | 否则老库升级断档，`check` 会报缺必填字段 |
| 约束 | 技能内文件不得引用仓库级 `docs/` | 安装后这些路径不存在，链路会断（`validate` 的 `E_LINK` 只查技能目录内，跨目录靠人核） |
| 约束 | 规则以文档为源，脚本只判机器可判的部分 | 判据 J-01 至 J-12 中仅四条有确定性判定，其余靠语义 |

## 上下文与边界

| 外部对象 | 用途 | 交互方式 | 不可用时 |
|---|---|---|---|
| 宿主 agent | 触发技能、派子代理、执行脚本 | 读 `skills/material-vault/SKILL.md` 与各 md；命令行跑 `node scripts/*.mjs` | 不支持派子代理时只走采集与检索，调研明说做不到 |
| 作者（唯一用户） | 给素材、给写作需求、拍板归类 | 对话 | 无 |
| 文件系统 | 存素材库与过程记录 | Node `node:fs`，路径用 `node:path` | 无写权限时停止并说明 |
| 网络 | 仅调研员取材 | 子代理的 WebSearch/WebFetch | 无联网时停止调研，建议改走采集 |
| CI | 每次推 main 跑门禁 | `npm run validate`、`npm test` | CI 不可用时本地跑同一对命令 |

本项目不负责：

- 写书本身，归写书项目。
- 整本书的结构化拆解，归拆书项目。
- 与 Enki、网文写作知识库的联动，人工引用即可。
- 市场情报（扫榜、签约动向），产品明确排除。
- 素材原文的长期保管，归用户的原文目录。

## 构建块

| 模块 | 路径 | 职责 | 依赖 |
|---|---|---|---|
| 技能入口 | `skills/material-vault/SKILL.md` | 何时用、两问调度、输入输出与停止条件 | 无 |
| 流程 | `skills/material-vault/workflows/` | 一组步骤的动作与停止条件，文件名序号即执行顺序 | 参考件、版式、子代理 |
| 参考件 | `skills/material-vault/references/` | 类型注册表（S-）、入库判据（J-）、权威源分级（S-12 至 S-17） | 无 |
| 版式 | `skills/material-vault/assets/素材卡版式.md` | 卡的字段骨架，产卡时拷贝 | 无 |
| 子代理任务书 | `skills/material-vault/agents/` | 采集员通用契约＋四张桶差异页＋调研员 | 参考件 |
| 卡格式契约 | `skills/material-vault/scripts/cardFormat.mjs` | 字段表、索引列、四个枚举、私有默认值、机器可判的字段校验 | 无 |
| 库接口 | `skills/material-vault/scripts/vault.mjs` | 十四个 interface：`writeCard`（校验＋落卡＋修索引）、`checkVault`（索引与卡逐列对账）、`rebuildIndex`（从卡重算索引）、`indexCard`（补一行）、`findCards`（四级收窄查重）、`upgradeVault`（跨版本升级）、`detectVault`（三层定位）、`initVault`（建库）、`cardEdit`（改一行）、`cardDelete`（移进回收站）、`cardRestore`（从回收站找回）、`cardMerge`（把一张并进另一张）、`cardMove`（改桶与类型族并挪文件）、`runCli`（子命令分发，io 可注入） | `node:fs`、`node:path`、卡格式契约 |
| 静态校验 | `scripts/validate.mjs` | 查 `skills/` 结构、frontmatter、流程小节、链接、README 技能表 | `node:fs` |
| 骨架生成 | `scripts/init-skill.mjs` | 从 `templates/skill/` 生成新技能 | `templates/` |
| 提交钩子 | `scripts/install-hooks.mjs` | 装 pre-commit，跑 validate 与 test | `.git/hooks` |
| 仓库测试 | `test/` | 静态检查与一致性检查，`node:test` | 无 |
| 行为用例 | `evals/cases/` | 需要真实 agent 的冒烟用例，人工跑 | 无 |

依赖方向：`SKILL.md → workflows → (references | assets | agents)` 单向，不反向引用；`vault.mjs → cardFormat.mjs`，反过来不行；`vault.mjs` 只被 workflows 以命令行调用，不 import md 内容。字段名的事实源是 `cardFormat.mjs`，`assets/素材卡版式.md` 是它的投影，由 `test/cardFormat.test.mjs` 钉住（契约里多一个字段而版式没跟，测试即失败）。仓库级 `scripts/` 不依赖 `skills/`，但 `test/` 可以 import 技能内脚本——这是唯一跨目录的读依赖。

## 运行时视图

| 场景 | 触发 | 步骤 | 产出 | 失败时 |
|---|---|---|---|---|
| 主流程·采集产卡 | 用户带素材上门并选定类型 | 1 入口两问定桶与类型；2 库定位（`vault.mjs detect`／`init`）；3 `01-采集.md` 派采集员（通用任务书＋差异页）；4 采集员返回素材点，主线程核必需字段；5 按版式组装卡 JSON，`vault.mjs write` 落卡并同步修好索引（一步，不再单独重算索引）；6 `vault.mjs check` 复核 | 卡文件＋INDEX.md | 采集员两次缺字段→停并交回入口；`check` 报错→不宣布完成，按报错改卡 |
| 主流程·老库升级 | 打开库发现 `VAULT.md` 版本落后 | 1 `vault.mjs upgrade --vault <根> --dry-run` 看清单；2 去掉 `--dry-run` 执行；3 逐卡补字段、失败卡进清单；4 重写 `VAULT.md` 的版本；5 `check` 复核 | 升级后的卡与身份证 | 坏卡跳过并计入清单，结束时退出码 1，已升级的卡不回滚（下一步重跑幂等） |
| 主流程·卡管理 | 用户说"这张要点写错了""删掉这张""并进那张""挪到剧情桥段" | 1 入口判为卡管理；2 读 `04-卡管理.md`，按 INDEX.md 找到目标卡的相对路径；3 调 `vault.mjs card edit／delete／restore／merge／move` 之一，一次一个动作；4 动作内部走 `writeCard` 落卡与修索引，删卡与合并另把卡连同原相对路径移进 `已删卡片/`；5 `check` 复核 | 改后的卡与索引；`已删卡片/` 下的回收副本 | 目标卡不存在、路径越界、新路径已存在、restore 原位置被占用→退出码 1 并说明，不改任何文件；缺参数→退出码 2 |
| 主流程·库定位 | 第一次用、或任何流程开始前要确定库在哪；用户说「你帮我归」 | 1 `vault.mjs detect`（给了路径带 `--vault`）读三态；2 「指定」与「就近」都还要核 VAULT.md 在不在，无身份证转建库；3 「未找到库」只给「新建」与「指向已有」两选，选新建跑 `init`，选指向已有则让用户给路径再 `detect`；4 `init` 后跑 `check` 复核；5 帮我归时按注册表「适用条件」的「素材是……」半句给一条建议并附理由，两次否决转两问 | 库根；帮我归另产出桶、类型族、子类三元组 | `detect` 退出码 1 → 不自动建库，等用户选；`init` 后 `check` 非 0 → 不宣布建好；两次否决 → 交回入口走两问 |
| 主流程·浏览 | 用户说「看看库里有什么」 | 1 读 `INDEX.md`，按「桶」列数四组行数；2 从「相对路径」列取卡文件名里的 `YYYYMMDD` 段倒序取 5 条，不读卡；3 用户点类型族或子类时按对应列筛，只给卡名与要点；4 全程不写文件 | 对话内三份清单，不落盘 | 缺 INDEX.md → 交回入口走 05 库定位；用户要正文或摘录 → 交回入口走 03 检索；用户顺带要改卡 → 交回入口走 04 卡管理 |
| 主流程·检索 | 用户提出写作需求 | 1 按需求推类型族；2 读 INDEX.md 筛候选；3 逐卡按 J-04 判相关性，时效敏感的先看时效状态；4 组织回复带卡路径 | 对话内清单，不落盘 | 索引不存在→停并说明库未建；候选为 0→如实说无匹配，不编造 |
| 失败流程·调研降级 | 只有主题且宿主无联网 | 1 派调研员；2 连续失败或白名单无联网工具；3 停止并返回已完成部分 | 未覆盖面说明 | 交回入口，建议改走 01 采集；不产卡、不伪造来源 |

## 横切关注点

| 关注点 | 做法 | 位置 |
|---|---|---|
| 错误处理 | 退出码固定 0 成功、1 业务失败、2 参数错误、3 环境缺失；仓库级脚本的 `E_*` 码只在 `02-脚本与测试.md` 的表里，新增须同次登记；`vault.mjs` 不引入 `E_*` 码，只输出中文 stderr＋退出码，避免与那张表分叉 | `scripts/`、`skills/material-vault/scripts/` |
| 配置 | 无配置文件。库根取 `--vault`，缺省 `./素材库/`；调研规模缺省 8 条 | `vault.mjs`、子代理任务书 |
| 日志 | 不写日志文件。调研过程记录写 `辅助内容/临时文件/<项目>/<日期>_<目的>/`，不进库 | `02-调研采集.md` |
| 安全 | 「私有」为「是」的卡不出现在任何分发产物（示范库、引用包、导出）；不整段拷原文；覆盖已有文件须显式 `--force`；写入库根之外的路径一律拒绝 | `vault.mjs`、`04-卡管理.md` |
| 写盘原子性 | 改卡与升级均先写同目录临时文件再 `rename`，中断不留半截卡 | `vault.mjs` 的统一写入口 |
| 编码 | 所有文本文件 UTF-8 无 BOM；`gitattributes` 固定 `*.md text eol=lf` 之外的平台差异 | `.gitattributes` |
| 幂等 | 索引是派生视图，可随时从卡重建（`index rebuild`）；两条写索引的路径（`writeCard` 的 upsert 与 `rebuildIndex`）共用同一套按相对路径排序，产出逐字相同，故重建可反复跑；升级先比较渲染结果再决定是否写盘，内容没变就一个字节都不写，故重跑不改内容也不改 mtime | `vault.mjs` 的 `writeIndex` 与 `upgradeVault` |

## 架构决策

| 编号 | 决策 | 理由 | 替代方案与代价 | 日期 |
|---|---|---|---|---|
| D-01 | 零依赖，只用 `node:` 内置模块 | 技能要能被 `npx skills add` 直接装走，装包会破坏这一点；也让 CI 不需要 install | 引 yaml 解析器或依赖库：需 lockfile 与网络，安装面扩大到使用者机器 | 2026-10-23 |
| D-02 | 素材库的全部读写收口到 `vault.mjs` 一个文件 | 定位、升级、卡管理、复审、库况都要解析同一套卡格式；分散实现必然各自漂移，且格式演进要改多处 | 每个功能一个脚本：解析逻辑重复四份，改字段必漏 | 2026-10-23 |
| D-03 | 索引（INDEX.md）是派生视图，由 `index rebuild` 从卡重建 | 手改文件会改坏索引；重建让索引漂移成为可修复问题而非不可见问题 | 增量追加并手工维护：删卡、挪类型时容易漏行 | 2026-10-23 |
| D-04 | 类型注册表「动作」列写成机器可解析的固定段式 | 入口菜单、采集维度、落卡路径、eval 路径都从它推导，段式让漂移在测试里现形 | 代码内维护枚举：与文档双源，必然有一边过期 | 2026-10-23 |
| D-05 | 卡格式版本化在 `VAULT.md`，加减字段即升 `SCHEMA_VERSION` | 老库散落在用户机器上，没有版本号就无法判断该不该升级 | 无版本、按缺字段探测：分不清「旧格式」与「填漏了」 | 2026-10-23 |
| D-06 | 「私有」做成通用卡字段，不只硬编码在点子族 | 一条规则同时覆盖 F-11 示范库与 F-17 点子不外流，用户也能把任意卡标私有不分发（Q-06 已决） | 只限点子族：将来要保密别的类型得再改一次格式 | 2026-10-23 |
| D-07 | 判据只把确定性判定交给脚本，其余靠人核 | J-03 字数、J-06 时效取值、J-09 来源等级、J-13 私有取值可机器判；切分与相关性要让模型判断，硬编码会误伤 | 全部交脚本：语义判据写不出阈值，只能造假通过 | 2026-10-23 |
| D-08 | 采集员用「通用任务书＋桶差异页」两件套，不写四份完整任务书 | 四份逐字同构 80%，改共性契约要改四处，漏一处即漂移 | 每桶一份完整任务书：重复度高，改一次要核四遍 | 2026-10-23 |
| D-09 | 库接口改为子命令＋`--长名` 参数，并支持 `--json` 与 `--help` | 与 `02-脚本与测试.md` 的接口约定一致；位置参数无法区分「漏库根」与「库根写错」 | 保留 `<子命令> <库根>` 位置参数：不符合标准，且不好加第二组参数 | 2026-10-23 |
| D-10 | 「私有」批一随新卡写入且暂不必填，批三转必填并同批升版本 | 字段与升级器若同批上线，必然出现「已按新格式产卡、库还记旧版本」或「升级器未到、老库已按新规则报缺字段」的窗口；拆成两批把窗口关掉 | 同批上线：老库在批一至批三之间 `check` 失败，用户会以为库坏了 | 2026-10-23 |
| D-11 | 卡格式契约独立成 `cardFormat.mjs`，`vault.mjs` 依赖它，不反向 | 字段表若留在 `vault.mjs`，仓库级测试要 import 一个含文件系统副作用的模块才能拿到常量；独立成无副作用的纯 module，测试与将来的审批菜单都能读它 | 全部塞进 `vault.mjs`：一个文件既管契约又管 IO，测试要写盘才能验字段 | 2026-10-23 |
| D-12 | `writeCard` 按「盘上的值打底、本次传入的覆盖」合并，不整卡覆盖 | 升级器写进「历史字段」的老值、以及调用方本次未提及的字段，整卡覆盖会蒸发，正好违反 F-10 的「被删字段的老值不丢」 | 整卡覆盖：升级与改卡每次都要传全字段，漏一个就丢数据 | 2026-10-23 |
| D-13 | `vault.mjs` 的 `runCli` 接可注入的 io、返回退出码，不调 `process.exit` | 原先退出码藏在 `process.exit` 里，只能起子进程才验得到，而受限环境禁止子进程管道（EPERM），这批用例就只能整组跳过，门禁形同虚设。io 一注入，同一接口在生产接 stdout、在测试接数组 | 保持 `process.exit`：CLI 的全部行为只能靠 spawn 验，沙箱里永远测不到 | 2026-10-23 |
| D-14 | 仓库级 `scripts/` 与技能内 `vault.mjs` 各自实现 CLI 出口，不抽公共 `runCli` | 交付物只有 `skills/`，仓库级模块装到使用者机器上并不存在；抽公共模块会让技能要么依赖一个不存在的文件，要么把仓库脚本一起打进交付物 | 抽一个公共 `scripts/cli.mjs` 给四处共用：技能安装后找不到它 | 2026-10-23 |
| D-15 | `upgradeVault` 先渲染成文本与盘上原文比较，相同则跳过不写 | A-06 要求重跑升级后内容与 mtime 均不变；`writeAtomic` 无条件 rename 会让每次重跑都刷新 mtime，升级就不幂等。比较渲染结果是唯一不依赖时钟的判法 | 无条件重写：每次 upgrade 都刷新全部卡的 mtime，备份与同步工具会把整库当成新改动 | 2026-10-23 |
| D-16 | 删卡不真删，卡连同原相对路径移进 `<库根>/已删卡片/`；`restore` 是逆操作 | F-14 要求「删错了能找回」。保留原相对路径意味着找回不需要任何额外记录，目录结构本身就是那张映射表；真删则找回只能靠备份 | 删进 `已删卡片/` 但拍平文件名：同名卡与祖先路径都会撞，且找回时不知道放回哪个桶 | 2026-10-23 |
| D-17 | 卡管理不在 `vault.mjs` 里另起写路径，五个动作内部都走 `writeCard` 落卡 | 校验、补默认值、落卡、修索引都收在 `writeCard` 一处；另写一条渲染路径，格式一演进就会有两条要同步维护的渲染实现（呼应 D-02） | 五个动作各自 `writeAtomic`：改字段与整卡重写会渲染出两种不同的卡 | 2026-10-23 |
| D-18 | 只有 `card move` 能改「桶」「类型族」，`card edit` 拒绝这两行并指向 `card move` | 这两行同时是字段与目录名，改成「允许 edit 改字段、人自己搬文件」就必然出现字段与位置不符的卡，而 `check` 抓不出（它只查字段与索引是否一致） | 允许 `card edit` 改桶与类型族：文件留在旧目录，检索仍按旧路径命中 | 2026-10-23 |
| D-19 | 「帮我归」把注册表「适用条件」列读成「只取『素材是……』半句」，不改注册表措辞 | 这一列写作「用户选定××桶、素材是……」，桶的选择在采集时是入口第一问给的前置条件，在帮我归时却正是要得出的结论；同一列两处语义相反，硬改注册表会让「不适用时」的改道句与采集侧口径一起漂。判据只留在流程一处（`05-库定位.md` 第 5 步），注册表仍是唯一事实源 | 改注册表措辞让两用兼容：`test/registry.test.mjs` 解析的是「动作」列，改「适用条件」不破坏它，但采集与检索两处引用这列的语境要一起重写，风险大于收益 | 2026-10-24 |
| D-20 | 浏览的「最近新增 5 张」按卡文件名的 `YYYYMMDD` 段排序，不读卡的「采集日期」字段 | `INDEX_COLUMNS` 里没有采集日期列，读它就得打开卡，而 F-16 明写「不读卡正文」——为排个序把整库卡正文拉进上下文，与本流程省上下文的目的相反。文件名由 `01-采集.md` 第 4 步的路径规则决定，与卡内日期同源；取不到日期段的不合规卡跳过并计数，不猜 | 给索引加一列「采集日期」：要改契约、版式、`check` 的逐列对账与全部老库的索引重建，为一个排序功能动格式版本不划算 | 2026-10-24 |
| D-21 | 查重的 `find` 子命令：一个筛选项都不给时**报参数错误**（退出 2），不返回整库；只读 INDEX.md，不打开卡正文 | F-19 要消掉的是「整表翻」，若允许空筛选就等于把那件事又放回来了，而调用方还以为是「收窄了」。桶名拼错同理：返回 0 行会被读成「库里没有」，其实是名字写错，故先验桶名再筛。只读索引是因为「库里有没有这个对象」看卡名与要点就够，判「内容是否重复」才需打开卡，那是调用方（采集流程第 4 步）的事——接口不该替它决定读多少 |

## 质量属性与风险

| 属性 | 场景 | 判据 | 现状 |
|---|---|---|---|
| 正确性 | 产卡后索引与卡一致 | `vault.mjs check --vault <根>` 退出码 0，索引行数＝卡数 | 达标：`writeCard` 写卡同时修索引；`check` 把索引当派生视图逐列对账（卡改了要点而索引没跟，这种漂移也抓得出）；`index rebuild` 可把任意分叉一次抹平 |
| 可靠性 | 升级中途失败 | 失败卡计入清单、退出码 1、重跑幂等 | 未测（升级器待建） |
| 可维护性 | 加一个类型族 | 注册表加一行后 `npm test` 仍全绿 | 达标：`registry.test.mjs` 九条守 |
| 可移植性 | 库拷到写书项目接着用 | 只改路径即可用，无绝对路径入库 | 达标：卡内只存相对路径 |
| 性能 | 千卡库校验 | 不超过 2 秒 | 未测 |
| 兼容性 | 老格式卡可读 | 缺新字段读出为空字符串，不抛错 | 达标：`readCard` 按行解析，缺行不报错 |

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-01 | 索引与卡不一致（手改、脚本中途失败） | 检索漏卡或指向不存在的文件 | `index rebuild` 重建＋`check` 比对；CI 不查库，靠运行时自查 |
| R-02 | 中文路径在 Windows 与 CI 上编码不一致 | 文件找不到或卡名乱码 | 全链路 UTF-8 无 BOM，路径用 `node:path`，测试用含中文的临时目录 |
| R-03 | 写入非原子（`writeFileSync` 直写），中断留半截卡 | 坏卡进库，校验报错但原因难查 | 0.4.0 起改为先写临时文件再 `rename`；升级器逐卡独立，坏卡跳过 |
| R-04 | 判据十二条里仅四条机器可判 | 质量下限依赖采集员自律，冒烟用例覆盖不足 | 扩充 `evals/cases/`，每批交付带一条用例 |
| R-05 | 受限沙箱禁止子进程管道，CLI 测试整组跳过 | 门禁在沙箱里形同虚设 | 统一 EPERM 探测并写明跳过原因；`vault.test.mjs` 目前缺这条护栏，待补 |
| R-06 | 同一流程在 `SKILL.md`、PRD、技术文档各描述一遍 | 三处对不上时不知道信谁 | PRD 只写产品口径，流程细节只在 `skills/`；本文件只写分层与取舍 |
