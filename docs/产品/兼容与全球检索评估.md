## 本轮结论

先把现有中文素材库做成按能力执行的独立技能，再扩大取材范围。用户已选择本轮完成兼容与全球检索，保持中文、两问、卡格式和旧库数据；不在本轮翻译产品、调整收费或上架市场。

## 产品经理视角

须弥解决的是个人积累难整理、难找回、难迁移的问题。真正交付给作者的价值是能解释作用机制的素材与按写作需求取回的参考，而非分类数或子代理数量。长期应观察作者是否接受提炼结果、能否找回旧料、是否在后续写作中再次使用；这些仍是待试用验证的产品假设，工程测试不能代替。

| 优先级 | 现状与影响 | 处理 |
|---|---|---|
| 本轮 | 安装技能不等于能执行脚本、联网或派工，统一宣传支持会让用户无法判断能用哪些功能 | 按能力分层说明，逐宿主记录实测状态 |
| 本轮 | 默认大陆来源与全球取材目标冲突，强制境外标签不能说明证据质量 | 全球默认、用户指定范围优先，追溯主体、语言与译述性质 |
| 本轮 | 私有标记容易被理解为整条数据链都保密 | 说明其约束引用包出口；不宣称加密或控制宿主的数据处理 |
| 后续优先 | README 强调分类由系统负责，实际两问仍让作者先学分类 | 单独验证“已知类型直接执行、歧义时单次确认”的交互；本轮保留现有两问 |
| 后续优先 | 首次使用要先理解分类、库位置与示范库 | 以“收自己的第一张卡，并用写作需求找回”为首次旅程验收目标 |
| 后续 | 公开分发与个人维护、当前不接收反馈的定位尚有冲突 | 扩大试用前确定支持范围、反馈入口与维护承诺 |
| 后续 | 跨语言原名与译名可能被当成不同对象 | 先保留原名、语言与出处；别名匹配需要单独设计，现有对象归一化不保证译名等价 |

全球取材与服务全球语言用户是两项不同工作。这一轮扩大输入来源，卡片与交互仍使用中文；不要把它宣传成已经完成国际化。

## 开发工程师视角

已有基础适合移植：标准 SKILL.md、随技能分发的脚本和参考件、零第三方 Node 依赖、普通 Markdown 数据库及稳定 CLI。主要障碍在运行时指令：固定工具白名单、把联网能力等同于子代理能力、按地域过滤来源，以及脚本相对路径可能随宿主工作目录改变。

执行规则以 `skills/material-vault/references/宿主能力适配.md` 为事实源，产品与验收以 PRD 的 F-34/A-16 为准。本轮不增加宿主专属分叉、不改卡格式，也不把可选连接器作为本地库的依赖。

| 层 | 职责 | 兼容边界 |
|---|---|---|
| 技能与任务书 | 分类、抽取、证据判断与流程 | 主线程和子代理使用相同任务与返回契约 |
| 宿主工具 | 文件权限、执行、搜索、读取、浏览器、派工 | 按当前会话实际能力选择；没有该能力就报告限制 |
| 可选连接器 | 补平台搜索、正文、字幕等通道 | 不自动安装、登录、更新或更改配置 |
| 库脚本 | 校验、写卡、查重、索引和管理 | 写库需要 Node 与文件权限；只加载文本不能替代 |

代码层还有后续维护成本：`vault.mjs` 集中承载较多职责，部分测试主要断言文档措辞。后续宜围绕稳定接口拆开职责、增加真实旅程验证；不在本轮兼容改动中做大规模重构。

## 已核对的外部依据

核对日期为文件头日期。下面是上游文档所述能力，不代表须弥在对应宿主已完成实机验收。

- [Codex 官方技能文档](https://developers.openai.com/codex/skills)：技能可包含指令、参考资源与脚本，并按需加载；本地技能发现与执行权限仍是不同问题
- [Claude Code 官方技能文档](https://code.claude.com/docs/en/skills)：采用 Agent Skills 标准，并有宿主自己的扩展；不能把某宿主的扩展字段或工具名当成所有宿主的共同接口
- [Cursor 官方技能文档](https://cursor.com/docs/skills)：技能可以包含脚本、模板与参考件，执行依赖当前 agent 的工具；支持格式不代表已授予文件、运行时与联网权限
- [Agent-Reach 上游 README](https://github.com/Panniantong/Agent-Reach)：通过 CLI 接入不同平台的搜索与读取等能力，各渠道的登录、转写和可用条件不同。它补访问通道，不能代替须弥的分类、来源独立性和正文真实性判断；须弥此前只有宿主工具约定，没有内置该程序

## Agensi 邀请的含义

[Agensi 官网](https://www.agensi.io/)公开展示技能市场、创作者入口及连接器，并说明技能可经连接器加载。本轮没有注册、上传、发布或购买，也没有独立验证邮件中每月 150,000 访客的数据；邮件和平台自述不能证明须弥的作者用户会被触达或愿意付费。

对须弥最先需要验证的不是价格，而是交付方式：上传的参考文件与 Node 脚本是否可被宿主取得、相对路径如何解析、能否在用户选择的目录执行，以及更新是否影响用户库。仅经连接器返回 SKILL.md 文本的环境，应按能力降级，不能宣称完整入库可用。平台对随包脚本的具体交付方式本轮尚未确认。

可以把市场视为一个待验证的分发渠道。中文技能可先服务会使用这些宿主的中文作者；是否提供双语入口、主题包或商业支持，应由后续作者试用结果决定。

Agensi 的[配套文件说明](https://www.agensi.io/learn/how-to-write-skill-md-supporting-files)明确介绍随技能包含参考件与脚本。文件可打包不等于已经验证其连接器能在目标会话取回完整资源、定位脚本并执行 Node，须弥仍需在该分发路径实测闭环。网站与营销材料中的增长和收入说法不作为本项目的商业验证。

## 验证范围

本轮区分静态契约、能力模拟、当前 Codex 会话中的真实执行，以及其他宿主实机验收。仓库测试通过只说明对应检查成立。Claude Code、Cursor、Gemini CLI 等的实际工具授权和完整旅程仍需分别实测，不以产品名或支持标准推定通过。

每个目标宿主至少复核：加载技能、首卡落库、重复补卡、检索、私有卡导出过滤、无网降级、无派工执行，以及主线程与子代理工具不一致时的回退。行为用例见 `evals/cases/material-vault-宿主兼容.md`。
