## 背景与问题

作家写书靠平时攒的东西：一个像路飞的主角、一段退婚的开局、一个"修士记不住事就折寿"的点子。这些东西散在脑子里、聊天记录里、截图里。问题有三个：

1. 记不住细节。想用时只剩"我好像见过类似的"。
2. 找不到。笔记翻半天，写作现场等不起。
3. AI 用不上。这些东西不在任何 AI 能读的地方。

自己记笔记为什么不行？因为没人有精力天天整理，笔记必然烂掉。Sumeru 的办法：素材进来的那一刻，由子代理（专职的 AI 帮手）自动整理成统一格式的卡片存进库；写作要用的时候，按类型一查就有。

## 目标

- 素材进门就成卡：贴一段素材，产出的卡字段齐全、要点不超过 40 字，不欠整理账。
- 找得回来：说一句需求（比如"我在设计一个反派"），拿到带出处的参考清单。
- 没素材也能收：只给主题（比如"查明朝锦衣卫"），派调研员上网查，查回来的东西同样成卡入库。
- 库能搬、能升级：库就是普通文件夹，拷到写书项目里接着用；卡格式升级了，一条命令把老卡升到新格式。
- 新用户开箱有货：项目自带一份示范库，装了技能就有一堆样例卡可看可学。

两条原则，优先级高于任何单条需求：

1. **点子不外流**：点子＝下一本书的选题，是机密。点子卡只存在用户自己的库里，永不进示范库、永不随任何方式分发。
2. **不会分类可以求助**：用户不知道素材算什么类型很正常，说"帮我归"就行，归类是系统的活，不是用户的功课。

## 非目标

- 不和 Enki、网文写作知识库打通（定位是独立技能；用到时人工引用，不自动联动）。
- 不做两个库之间的合并搬运（各自的库各自长；关联只在库内有效）。
- 不做多人共用（就一个人用，没有冲突场景）。
- 不做整本书的拆解（那是拆书项目的事）。
- 不代写书（只供料；写书是写书项目的事）。

## 用户与场景

| 角色 | 情境 | 目标 | 现在怎么解决 |
|---|---|---|---|
| 作者（本人，唯一用户） | 读书、看番、群聊里撞到好东西 | 当场收进库，不欠账 | 手记笔记，然后烂掉 |
| 作者 | 写书前或写书中要参考 | 按类型拿到带出处的卡 | 翻聊天记录、靠回忆 |
| 作者 | 只有主题没素材 | 派员上网查，查得干净 | 自己搜，噪音大、真假难辨 |
| 作者 | 卡写错了、重复了、不要了 | 改掉、并掉、删掉 | 无（只能手改文件，会改坏索引） |
| 写书项目中的作者 | 在书项目目录里长期攒料 | 库跟着书项目走，随用随升级 | 无 |
| 其他作者（装了技能的人） | 装完看到示范库 | 明白这是示范，自建自己的库 | 无 |

## 产品流程

### 第一次用（先探测，别急着问）

```
第一次触发技能
     │
     ▼
先看环境
 ├─ 用户已经说了库放哪 ────────► 直接用那个库
 ├─ 当前目录或上层已经有现成的库 ─► 直接接着用（这就是"无缝接入"）
 └─ 什么都没有
     │
     ▼
引导三选（只有这一次）
 ├─ 新建：在当前位置建 素材库/，写好库的身份证文件
 ├─ 指向已有文件夹 ──► 是我们的库就接入；不是就问：当散料收编，还是另建
 └─ 收编散料 ──► 指一个装素材的文件夹，分批压成卡（先试采一小批）
     │
     ▼
进入日常使用
```

说明：库的"身份证文件"指库根下的 `VAULT.md`，记两件事——这是 Sumeru 的库、卡的格式是第几版。认身份证就是认库，别把普通文件夹误当库。

### 日常使用（先问来意）

```
触发技能
  │
  ▼
先问来意
 ├─ 收素材，知道类型 ──► 选桶→选类型→贴素材 ────► 采集
 ├─ 收素材，不知道类型 ─► 帮我归：先描述→AI 给归类建议→
 │                       用户点头→进采集
 ├─ 查资料，只有主题 ──► 选类型→调研员联网取材 ──► 调研采集
 ├─ 找参考，有写作需求 ──────────────────────► 检索
 ├─ 改卡、删卡、合并卡、挪类型 ────────────────► 卡管理
 └─ 看看库里有什么 ────────────────────────────► 浏览
        │
        ▼
卡统一落进一个库（放哪：用户指定＞就近找现成库＞默认 ./素材库/）
```

采集、调研采集、检索三路已实现；卡管理、浏览、帮我归在 0.4.0 建（见里程碑）。

### 库升级

```
打开库时看身份证上的版本号
 ├─ 版本＝最新 ──► 正常用
 ├─ 版本落后 ────► 老卡照样能读（缺的新字段当空，不报错）
 │                 提示跑一条命令升级：
 │                 node scripts/upgrade-vault.mjs 库路径
 │                 → 机器能补的自动补；补不出的标"待补"
 │                 → 想补齐可以让 AI 读老卡补内容，补处标〔推断〕
 └─ 没有身份证（不是我们的库）─► 交回首次使用引导处理
```

## 产物结构

### 素材库（一个普通文件夹，放哪由用户定）

```
素材库/
├── VAULT.md                     ← 库的身份证：格式版本＋一句话简介
├── INDEX.md                     ← 总目录：一行一卡（卡名、桶、类型、子类、要点、时效、路径）
├── 已删/                         ← 删掉的卡先进这里，可找回
├── 攒料/
│   ├── 点子/                    └── 卡-<年月日>-<短名>.md
│   ├── 人设/  剧情桥段/  世界观设定/  意象氛围/
├── 学法/  ├ 技巧/  └ 语料/
├── 照例/  └ 切片/
├── 源料/  └ 现实/
└── 避雷/  └ 反例/
```

一张卡长什么样（格式的唯一依据在 `skills/material-vault/assets/素材卡版式.md`）：

```
卡-年月日-短名.md
├── 基本信息：卡名、桶、类型族、子类、来源、出处链接、来源等级、
│              采集日期、时效状态、要点（≤40 字）
├── 类型维度：该类型规定的字段逐行填，没有的写"未覆盖"
├── 正文：内容、原文摘录或事实要点、借鉴意图、已用在（书名＋章节，可空）、关联卡
```

### 技能本体（skills/material-vault/，装技能时装走）

```
skills/material-vault/
├── SKILL.md          ← 入口：问来意、分路
├── workflows/        ← 采集、调研采集、检索（卡管理、浏览在 0.4.0 加）
├── agents/           ← 五个子代理任务书（四桶采集员＋调研员）
├── references/       ← 类型注册表、入库判据、权威源分级
├── assets/           ← 素材卡版式
└── scripts/          ← upgrade-vault.mjs 升级脚本（待建）
```

### 项目仓库（Chained1001/sumeru，随 git 公开）

```
sumeru/
├── skills/material-vault/   ← 技能本体
├── 样例库/                   ← 示范库（待建），结构与素材库相同，但没有任何点子卡
├── docs/产品/PRD.md          ← 本文件
└── ...                      ← 校验、测试、模板等工程文件
```

## 假设、约束与依赖

| 类型 | 内容 | 不成立时 |
|---|---|---|
| 假设 | 宿主能上网、能派子代理（已实测六次成立） | 上不了网就只走采集不走调研，明说原因 |
| 假设 | 子代理按任务书干活，缺字段能被核出 | 两次重派失败就停，交回用户 |
| 假设 | 库在几百张卡以内人工查重还行 | 超了就必须先做 F-19，否则重复卡会堆积 |
| 约束 | 零依赖：只用 Node 自带能力，不装任何包 | 装包会破坏随技能分发 |
| 约束 | 公开仓库：卡只存要点、短摘录、出处，不整段搬原文 | 越界＝违反版权与仓库纪律 |
| 约束 | 点子族的卡不进任何分发 | 进了＝把下一本书的选题公开剧透 |
| 约束 | 卡格式每次加减字段，同一次提交里必须更新升级脚本 | 不同步＝老库升级断档 |
| 依赖 | Node.js 24 及以上 | 版本不够，命令会中文提示 |
