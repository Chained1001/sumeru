## 背景与问题

作家写书靠平时攒的东西：一个像路飞的主角、一段退婚的开局、一个"修士记不住事就折寿"的点子。这些东西散在脑子里、聊天记录里、截图里。问题有三个：

1. 记不住细节。想用时只剩"我好像见过类似的"。
2. 找不到。笔记翻半天，写作现场等不起。
3. AI 用不上。这些东西不在任何 AI 能读的地方。

自己记笔记为什么不行？因为没人有精力天天整理，笔记必然烂掉。Sumeru 的办法：素材进来的那一刻，由子代理（专职的 AI 帮手）自动整理成统一格式的卡片存进库；写作要用的时候，按类型一查就有。

## 目标

- 素材进门就成卡：贴一段素材，产出的卡字段齐全、要点不超过 40 字，不欠整理账。
- 找得回来：说一句需求（比如"我在设计一个反派"），拿到带出处的参考清单。
- 没素材也能收：只给主题（比如"查明朝锦衣卫"），派调研员上网查，查回来的东西同样成卡入库。
- 库能搬、能升级：库就是普通文件夹，拷到写书项目里接着用；卡格式升级了，一条命令把老卡升到新格式。
- 新用户开箱有货：项目自带一份示范库，装了技能就有一堆样例卡可看可学。

0.4.0 增补三条，判定方式写在验收标准里：

- 库能被认出：库根有 `VAULT.md` 的目录被直接接入，没有的走首次引导，二者都不靠读卡猜。
- 索引不再手工维护：卡增、删、改、挪之后跑一条命令，索引与卡一致（行数相等、路径全部可达）。
- 格式版本可升级：格式第 1 版的老库跑一条命令后，必填字段补齐、`vault check` 退出码 0，重跑不产生二次改动。


两条原则，优先级高于任何单条需求：

1. **点子不外流**：点子＝下一本书的选题，是机密。点子卡只存在用户自己的库里，永不进示范库、永不随任何方式分发。落地口径：任何卡的「私有」标记为「是」即不分发，点子族新建卡默认私有（Q-06 已决）。
2. **不会分类可以求助**：用户不知道素材算什么类型很正常，说"帮我归"就行，归类是系统的活，不是用户的功课。

## 非目标

- 不和 Enki、网文写作知识库打通（定位是独立技能；用到时人工引用，不自动联动）。
- 不收市场风向（扫榜、平台签约动向等市场情报；原因：用户拍板，与知识库排除市场数据的原则一致）。
- 不收单书过程资产（伏笔账本、状态台账这类只服务一本书的东西；原因：它们是写书项目的件，不是可复用素材）。
- 不做两个库之间的合并搬运（各自的库各自长；关联只在库内有效）。
- 不做多人共用（就一个人用，没有冲突场景）。
- 不做整本书的拆解（那是拆书项目的事）。
- 不代写书（只供料；写书是写书项目的事）。

## 用户与场景

| 角色 | 情境 | 目标 | 现在怎么解决 |
|---|---|---|---|
| 作者（本人，唯一用户） | 读书、看番、群聊里撞到好东西 | 当场收进库，不欠账 | 手记笔记，然后烂掉 |
| 作者 | 写书前或写书中要参考 | 按类型拿到带出处的卡 | 翻聊天记录、靠回忆 |
| 作者 | 只有主题没素材 | 派员上网查，查得干净 | 自己搜，噪音大、真假难辨 |
| 作者 | 卡写错了、重复了、不要了 | 改掉、并掉、删掉 | 无（只能手改文件，会改坏索引） |
| 写书项目中的作者 | 在书项目目录里长期攒料 | 库跟着书项目走，随用随升级 | 无 |
| 其他作者（装了技能的人） | 装完看到示范库 | 明白这是示范，自建自己的库 | 无 |

## 产品流程

### 第一次用（先探测，别急着问）

```
第一次触发技能
     │
     ▼
先看环境
 ├─ 用户已经说了库放哪 ────────► 直接用那个库
 ├─ 当前目录或上层已经有现成的库 ─► 直接接着用（这就是"无缝接入"）
 └─ 什么都没有
     │
     ▼
引导两选（只有这一次；三选里的「收编散料」在 0.5.0 随 F-08 上线）
 ├─ 新建：在当前位置建 素材库/，写好库的身份证文件
 └─ 指向已有文件夹 ──► 有身份证就直接接入；没有就问：在这里建库，还是另建
     │
     ▼
进入日常使用
```

说明：库的"身份证文件"指库根下的 `VAULT.md`，记两件事——这是 Sumeru 的库、卡的格式是第几版。认身份证就是认库，别把普通文件夹误当库。

0.4.0 的边界：探测与接入做，「收编散料」不做——缺批量采集能力，指个文件夹进来只会产出一张张散卡，口径没定就压卡等于制造返工。指向的文件夹没有身份证时只给「在此建库」与「另建」两选，不引入第三选。

### 日常使用（先问来意）

```
触发技能
  │
  ▼
先问来意
 ├─ 收素材，知道类型 ──► 选桶→选类型→贴素材 ────► 采集
 ├─ 收素材，不知道类型 ─► 帮我归：先描述→AI 给归类建议→
 │                       用户点头→进采集
 ├─ 查资料，只有主题 ──► 选类型→调研员联网取材 ──► 调研采集
 ├─ 找参考，有写作需求 ──────────────────────► 检索
 ├─ 改卡、删卡、合并卡、挪类型 ────────────────► 卡管理
 └─ 看看库里有什么 ────────────────────────────► 浏览
        │
        ▼
卡统一落进一个库（放哪：用户指定＞就近找现成库＞默认 ./素材库/）
```

采集、调研采集、检索、卡管理、库定位（含帮我归）、浏览六路已随 0.4.0 交付（见里程碑）。

### 库升级

```
打开库时看身份证上的版本号
 ├─ 版本＝最新 ──► 正常用
 ├─ 版本落后 ────► 老卡照样能读（缺的新字段当空，不报错）
 │                 提示跑一条命令升级（先空跑看清单，确认后去掉 --dry-run 执行）：
 │                 node scripts/vault.mjs upgrade --vault 库路径 --dry-run
 │                 → 机器能补的自动补；补不出的标"待补"
 │                 → 想补齐可以让 AI 读老卡补内容，补处标〔推断〕
 └─ 没有身份证（不是我们的库）─► 交回首次使用引导处理
```

## 产物结构

### 素材库（一个普通文件夹，放哪由用户定）

```
素材库/
├── VAULT.md                     ← 库的身份证：格式版本＋一句话简介
├── INDEX.md                     ← 总目录：一行一卡（列名见 cardFormat.mjs 的 INDEX_COLUMNS）
├── 已删卡片/                     ← 删掉的卡先进这里，可找回
├── 故事零件/
│   ├── 开书点子/                └── 卡-<年月日>-<短名>.md
│   ├── 人物设定/
│   ├── 剧情桥段/
│   ├── 世界设定/
│   ├── 意象氛围/
│   └── 起名灵感/
├── 写作方法/
│   ├── 写作技巧/
│   └── 金句语料/
├── 作品案例/
│   └── 作品切片/
└── 现实避坑/
    ├── 现实见闻/
    └── 反面教材/
```

命名规则：所有目录统一四个字，用大白话，不用行话缩写——桶是「故事零件、写作方法、作品案例、现实避坑」，类型是「开书点子、人物设定、剧情桥段、世界设定、意象氛围、起名灵感、写作技巧、金句语料、作品切片、现实见闻、反面教材」。

一张卡长什么样：字段与取值的唯一事实源是 `skills/material-vault/scripts/cardFormat.mjs`，人看的骨架是 `skills/material-vault/assets/素材卡版式.md`（由 `test/cardFormat.test.mjs` 钉住两者一致）。本文件不重复字段清单。

「私有」是 0.4.0 新增的基本信息字段，取值只有「是」「否」两档；点子族（S-01）新建卡写「是」，其余族写「否」，用户可改。它同时承担 F-11 示范库过滤与 F-17 点子不外流两条需求，不另设第二个保密机制（技术取舍见 `docs/技术/技术文档.md` 的 D-06）。字段随批一加入，批三转必填并同批把格式版本升到 2：老库跑一次 `upgrade` 即可，升级器按类型族补默认值（S-01 是、其余否），此后缺这一行的卡会被 `check` 报错。

F-30（同一对象再积累＝补卡不建新卡）在 0.3.1 就标了「已交付」，落地方式是判据 J-05 加一句流程规矩。问题在于 J-05 的验证方式写的是「人工核对：索引无同对象双卡」——这是全库唯一一条**靠人眼在索引里找双卡**的硬判据，而采集时最容易失守的恰恰是它：AI 派了采集员、生成了卡、写进了库，事后没人会去索引里逐行比对「这两张是不是同一个人」。

## 假设、约束与依赖

| 类型 | 内容 | 不成立时 |
|---|---|---|
| 假设 | 宿主能上网、能派子代理（已实测六次成立） | 上不了网就只走采集不走调研，明说原因 |
| 假设 | 子代理按任务书干活，缺字段能被核出 | 两次重派失败就停，交回用户 |
| 假设 | 库在几百张卡以内人工查重还行 | 超了就必须先做 F-19，否则重复卡会堆积 |
| 假设 | 库内的索引可以从卡无损重建：每个必填字段都能从卡正文取到 | 取不到的字段在索引行留空并在 `rebuild` 结果里计数，不改卡去迎合索引 |
| 约束 | 零依赖：只用 Node 自带能力，不装任何包 | 装包会破坏随技能分发 |
| 约束 | 公开仓库：卡只存要点、短摘录、出处，不整段搬原文 | 越界＝违反版权与仓库纪律 |
| 约束 | 「私有」为「是」的卡不进任何分发产物，含示范库与引用包 | 进了＝把下一本书的选题公开剧透 |
| 约束 | 卡格式每次加减字段，同一次提交里必须更新升级脚本与版式 | 不同步＝老库升级断档，`check` 报缺字段 |
| 约束 | 库内一律存相对路径，不落绝对路径 | 库要能被拷进写书项目，绝对路径一拷就废 |
| 依赖 | Node.js 24 及以上 | 版本不够，命令会中文提示 |
